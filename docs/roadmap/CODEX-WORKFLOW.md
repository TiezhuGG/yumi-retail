# Codex 交互与可复制提示词

日期：2026-10-26。用户已发送S0开工指令并确认PostgreSQL与本机Docker Desktop；以下后续提示词仍按实际任务选择使用，不代表发布或真实支付已获授权。

## 1. 日常怎么使用

在Codex中打开本项目目录。当前聊天可继续使用；新聊天仍应绑定同一项目目录，并先读取README和状态记录，再按本次任务读取相关规范。无需每次重新上传yumi.md与7张图；它们已归档在docs/references，相关页面任务才需要查看对应图片。

根目录AGENTS.md用于持续项目规则。官方说明Codex会发现并读取适用的AGENTS文件，见[官方项目指令文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。仍应把这次具体目标写清楚，不假设AGENTS能代替任务描述。

有效提示包含结果、相关上下文、范围与验收；需求明确时不必规定每一个文件和操作步骤。参考[官方提示词说明](https://learn.chatgpt.com/docs/prompting)和[开发工作流示例](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex)。本文模板是本项目的实践建议，不是产品强制格式。

## 2. 第一条：选择PostgreSQL并开始S0

本项目已采用下列方向，接续任务先读取最新状态，避免重复初始化：

```text

按AGENTS.md和现有开发计划工作，先读取README、当前状态及ADR-002，
把AGENTS、架构、数据库、部署和任务文档同步统一，保留原始资料。

完成最小Taro编译、Nest/Prisma/PostgreSQL迁移与CRUD、事务回滚、
最后一件库存并发争抢验证，并记录实际通过的精确版本。
只安装所需稳定依赖，不直接使用latest，不接入真实支付。
系统级软件安装或重启需要时先明确具体操作；独立可完成部分继续推进。
完成后给出实际检查结果、未验证项、我需要做的动作和下一步。
```

数据库已确定PostgreSQL，不再使用MySQL替代版本的开工提示。

## 5. 后续继续与换聊天

```text
继续玉米百货项目。先读取README和docs/roadmap/DECISIONS-AND-STATUS.md，
核对当前代码与最近验证记录，选择开发计划中依赖已满足的下一条业务切片。
简要说明本次范围，然后完成实现和必要验证，并更新接续记录。
沿用已确认数据库、版本和业务规则；待确认参数保持开发样例标记。
```

一个切片完成或主题变化后可开新聊天；新聊天以仓库文档与代码恢复状态，不依赖复制全部旧聊天。不要安排多个聊天同时无协调地修改同一迁移、依赖锁或核心交易模型。

## 6. 调整UI时

```text
实现C05购物车，参考归档mini1.png中的布局和当前UI规格。
金额、选中状态和商品有效性按PRD与真实API，图片中的积分/促销不作为需求。
覆盖加载、空购物车、下架、缺货、数量不足和网络错误；
复用已有商品卡、价格与步进器，保持375逻辑像素下的可用性。
完成编译和适用验证，说明真机尚未验证的部分。
```

需要改样式时直接描述具体结果，例如“主按钮固定底部，长商品名最多两行，缺货原因要看得见”，比“再高级一点”更容易验收。

## 7. 报错、验收与安全专项

报错时提供发生页面、操作步骤、预期、实际结果及脱敏报错内容；Codex可以直接读取本地终端输出时无须反复粘贴日志。示例：

```text
收货入库点确认后出现错误，刷新发现库存已增加。
请复现并找出根因，检查事务和幂等，不要通过前端隐藏错误解决。
修复后验证正常过账、响应丢失后重试、重复点击和无权限操作，更新结果。
```

代码出现后可明确发起专项：

```text
对当前订单、库存、支付和退款代码做安全与一致性审查，
使用适用的security-best-practices技能，依据实际代码和可复现证据报告问题。
重点检查资源归属、骑手权限、金额篡改、重复请求、回调、密钥和上传。
不要把建议方案写成已存在漏洞；报告严重程度、位置、影响和验证结果。
```

发布前如需威胁建模，应明确使用security-threat-model并提供真实部署边界；技能安装不代表已自动执行审查。CI失败可明确要求使用gh-fix-ci，需实际GitHub访问与失败上下文。

## 8. 一次交付怎样判断完成

| 应看到的结果 | 不足以替代的说法 |
|---|---|
| 产物、启动入口、演示步骤 | “代码已生成” |
| 运行过的检查及结果 | “理论上应该没问题” |
| 交易与库存真实数据库结果 | “页面能点”“SQLite测试通过” |
| 微信开发者工具与真机记录 | “H5预览正常所以小程序通过” |
| 待办与未验证项准确更新 | “全部完成”，但支付/真机未测试 |

后续无需反复给Codex写角色设定。用“目标+范围+验收”提出任务，依据结果迭代即可。
