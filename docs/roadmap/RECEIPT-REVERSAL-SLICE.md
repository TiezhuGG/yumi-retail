# 收货入库逆向纠错切片 · 2026-10-28

本轮单据关联原已过账收货批次的一个库存位置，按整数件部分冲减误录数量。原收货单保持POSTED，原行、成本、日期、原流水不改；正确资料另建正常收货单。不是供应商退货、损坏报损、退款或账本修复接口。

开发默认：管理员/仓管申请、取消与过账；另一员工独立审批。DRAFT→APPROVED→POSTED，过账前可带原因CANCELLED。过账须明确确认已核验原记录与实物并提供说明。草稿不预扣额度，取消不改库存。正式SOP/分权待负责人确认。

每单一个已存在位置，quantity为1..100000；位置版本快照须在审批/过账匹配。批次累计已过账逆向数量≤原收货行quantity（不因盘盈恢复额度），且当前位置自由数onHand−reserved−blocked足够。三层库存同减onHand，reserved/blocked及隔离remaining不变。过期/停用位置可纠错，不会恢复任何可售资格。不处理增加数量、未知批次或跨仓。移位后可从同一原批次的新位置纠错，不可扣别批次补足。

所有写动作先校验仓库范围；审批/过账锁同一仓库SKU余额并重新核验原单已过账、额度、位置版本、盘点冻结、核对暂停及账本一致。取消只锁余额并终结申请，不清除冻结/核对暂停。成功同事务保存三层库存、两级新流水、单据、审计和稳定幂等结果，晚期失败全部回滚。数据库保护复合归属、不可变源、状态、独立审批、核验说明、原入库额度及正确流水证据。

验收：单据与数量闭环、多位置部分纠错、额度不被盘盈放大、预占/隔离保护、冻结/暂停/不平账拒绝、独立审核/版本/CSRF/角色/跨仓、同键20次重试、不同键争抢及单据并发过账、取消、晚期失败原键重试、数据库约束与既有66项回归。后台/H5以一次性合成数据演示，不代替实物或微信真机验收。
