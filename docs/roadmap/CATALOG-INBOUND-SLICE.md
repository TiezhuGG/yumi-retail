# 商品与收货切片：实现前边界

2026-10-27。沿用已锁定版本，无新依赖。目标：员工建分类/SPU/SKU→收货单草稿→审核→过账→上架→匿名小程序读取真实可售商品。

本轮提供最多两级分类、一个商品多个规格、固定整数分价格；商品草稿/上架/下架只通过专用动作。收货行有数量、成本和可选效期截止时间；效期管理SKU必须填写未来的绝对时间。库存按仓库/SKU汇总和收货批次记录，本轮批次固定DEFAULT货位，不提供移位、隔离/盘点/报损作业。后续拆独立库位明细时须迁移，不能绕过账本改数量。

收货单不可编辑，填错新建草稿；本轮审核允许同一员工（本地开发默认，正式分权策略待业务确认）。过账前重新检查仓库、SKU和效期。创建及所有写动作要求UUID Idempotency-Key；同主体/动作/对象/键绑定规范化输入，变更输入409；过账还通过单据状态与流水唯一约束阻止不同键重复加库存。事务任一步失败全部回滚。已过账单禁止编辑/删除，纠错逆向单后续实现。

权限：管理员/运营维护商品；管理员/仓管收货、审核、过账，且每次限定warehouse_id；拣货员只读库存，骑手不能访问仓库业务。库存和商品公开查询不含成本、员工或供应资料，只返回已上架、有效分类与SKU的销售资料和可售数量；不支持任意传warehouseId切换经营仓。单仓PUBLIC_WAREHOUSE_ID为服务端配置，无配置返回503，不自动取任意仓。

验收：草稿不可见；零库存不显示可购买；正常入库一致；同键重试/不同键并发只入一次；多SKU中途失败回滚；成本/数量非法拒绝；下架、仓库停用、分类停用、SKU停用和到期批次不可售；跨仓/骑手越权拒绝；公开响应无成本；分页有界；实际PostgreSQL集成+全构建+页面检查。小程序编译不等于微信工具/真机通过。
