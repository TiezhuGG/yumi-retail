# 批次/库位与库存核对：实施前边界

2026-10-27，沿用S2版本，不新增依赖。目标：从固定DEFAULT货位演进到真实库位/批次位置；同仓移位有成对流水，支持按SKU核对汇总、批次、位置和账本。

迁移先检查旧汇总=批次=旧流水的on_hand/reserved/blocked，失败则整笔迁移停止，不能静默修数。旧流水保持不可改；新建位置账本引用旧流水回填历史，原DEFAULT数量原样落位。StockLot数量暂留作兼容汇总缓存，真实位置另存StockPosition，后续业务同时维护。迁移时须停止旧API写入，新服务写位置与账本；不能混跑旧收货代码。

本轮库位为普通存储位，支持创建、查看、空库位启停；DEFAULT保留，不能停用。收货仍先入DEFAULT，再显式同仓移位；不接入跨仓调拨、不可售区转换、盘点/报损、订单预占。移位数量为正整数，携带源位置版本、目标库位与原因，仅移动未预占/未blocked数量；当前源位置存在任何预占时整位置拒绝移位，符合首期“禁止移动已预占库存”的边界。过期批次可物理移位但仍不可售。

所有写动作需会话、权限、Origin/CSRF与UUID Idempotency-Key；管理员/仓管管理和移位，拣货员仅查看无成本的批次位置，骑手不可访问。跨仓位置/库位禁止。按仓库/SKU余额锁串行收货、移位和核对；事务内数量、成对流水、业务单、审计和幂等结果一致提交，重试不重复移动。

核对每次针对一个SKU，保存不可改报告；检查汇总与批次/位置/主流水，以及逐批次、逐位置及逐业务流水的匹配，防止不同位置差额抵消。报告不自动修数；差异设置inventory_hold，可售变0并拒绝继续入库/移位。修复流程本轮不提供数量改写；解除暂停为独立动作，需原因、余额版本和重新完整核对通过，不因重复运行正常报告自动解封。

验收：带旧数据迁移保量且不改旧流水、旧不一致拒迁移；新收货一致；正常/同键重试/并发争抢移位；失败全回滚、越仓/角色/停用/预占/数量/旧版本拒绝；移位前后可售不变；过期仍不可售；核对发现汇总和位置相抵差异、触发销售暂停、拒绝无依据解除；账本不可改。真实PostgreSQL集成、原S2回归、构建/类型/规范和浏览器检查。真机/支付仍独立待验收。
