# 玉米百货｜MVP V1.0 研发执行计划

**项目代号：** `yumi-retail`  
**文档版本：** DEV-ROADMAP-V1.0  
**产品范围：** 单小区、单仓、自营商品、自行配送  
**前端：** Taro 4 / React / TypeScript  
**后台：** React / Vite / Ant Design  
**服务端：** NestJS / Prisma / MySQL  
**工程策略：** Monorepo + 模块化单体 + 持续集成  
**版本目标：** 首个能够运营真实订单的微信小程序

---

## P5｜结算、库存预占、订单和支付

目标：建立 V1 最关键、需要最严格测试的交易链路。

| ID | 开发任务 | 交付与验收 |
|---|---|---|
| YM-043 | 服务端结算报价 | 校验 SKU、价格、库存、营业时间、起送金额和配送费 |
| YM-044 | 确认订单 C06 | 地址、商品、运费、备注、金额与提交按钮 |
| YM-045 | 订单与订单快照数据模型 | 订单号、金额、地址、商品明细、状态 |
| YM-046 | 原子库存预占 | 数据库事务与条件更新，防止并发超卖 |
| YM-047 | 订单创建幂等 | 相同请求幂等键不重复产生交易 |
| YM-048 | 订单支付状态机 | 待支付、已支付、取消、支付结果待核实 |
| YM-049 | 微信支付 API v3 | 预支付、客户端调起参数、通知验签解密 |
| YM-050 | 支付主动查单与对账 | 避免前端失败但真实扣款的订单丢失 |
| YM-051 | 超时关单与释放预占 | 查单、关单和本地状态确认后安全释放 |
| YM-052 | 订单列表/详情与支付结果 | C07、C10、C11 完成真实数据绑定 |
| YM-053 | 交易异常自动化测试 | 并发、重复回调、超时竞争、网络中断 |

**阶段验收：** 用户可以真实下单并完成微信支付；后台出现一笔已支付订单；支付重复通知不会产生重复订单、重复扣库存或重复账务记录。

支付资质未准备好时，使用明确隔离的开发模拟支付适配器做业务联调；真实支付功能未通过联调之前，不得认为此阶段已经达到正式上线标准。

## 研发阶段全局完成标准

一个功能不应因为“页面已经能打开”就被标记为完成。

所有任务需满足：

- 业务行为与 PRD 一致。
- 前后端 API 类型和数据约定一致。
- 涉及权限的接口完成服务端鉴权。
- 关键异常状态有明确处理。
- 自动化测试实际运行通过。
- 关键操作具有日志或审计记录。
- 不包含硬编码生产秘钥。
- 文档与实际实现同步更新。
- 代码已经过 Review 并合入指定分支。

订单、支付、库存、退款四类任务需要额外完成幂等和并发验证。

**P0–P9 全部验收通过，才标记 `MVP V1.0 Released`。**
