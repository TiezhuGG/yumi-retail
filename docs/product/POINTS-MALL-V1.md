# 积分商城首发设计（2026-11-02）

状态：设计基线及实施接续。P1账户、发放和关联误发纠错已完成本地验证；P2–P5仍为计划，积分商城未上线。已确认的是新增积分商城、小程序与运营后台同时交付、优先实现上线；以下经营规则是建议，不能当作已确认配置。此次覆盖原PRD B03中排除积分的限制，其余营销限制继续有效。

## 1. 首发边界与上线方式

建议先做纯积分兑换实物商品：一个小区、一个仓库、现有自营骑手配送。复用商品SKU、地址、批次库存及仓配能力，兑换单与现金订单分开记账。首发每单一个SKU，可选择整数件数，独立立即兑换，不与现金购物车混单。

建议不收现金配送费、不设现金起送门槛；兑换积分价覆盖运营成本，后台配置单用户限兑与总兑换配额。该经营方案待确认，配置未确认不得开放生产兑换。若需要现金运费，必须增加真实支付、关单及积分现金联动退款后才能上线，不能临时套用普通购买付款流程。

本期不做积分充值、转让、提现、积分加现金、积分抵现、签到、邀请奖励、会员等级或抽奖。普通购物赠积分放第二阶段，避免现金交易尚未上线时首发无积分可用。

首发积分来源建议为运营有依据的人工发放：选择用户、填写数量、原因及业务凭据，由另一名授权人员审批后入账；不能默认赠送注册积分或虚构历史积分。没有可独立审批的人员时，先完成开发，由负责人确定正式发放职责后开放。

## 2. 积分规则

- 积分为整数，独立于人民币分；正数兑换价，不建立固定现金换算承诺。新账户余额0。
- 建议首版不设到期时间；未来如增加有效期，需单独设计积分批次、消耗顺序和通知政策，不追溯清零现有余额。
- 余额只能通过追加积分流水变化，禁止直接编辑余额、删除流水。来源、操作人、审批人、业务单据可追溯。
- 发放单：草稿→提交→批准并入账，或驳回/撤销；批准与入账同事务。发起人不得审批自己的发放；批准后只能另建冲正单。
- 人工扣减/冲正走独立审批且不允许扣成负数，余额不足进入待处理，不删除原发放记录。技术数值上限必须明确；业务单笔/每日预算在后台配置，未配置不开放发放。
- 兑换成功时立即扣积分并预占实物；不设等待支付。失败两者全部回滚。建议取消退还积分且释放限兑配额，完成兑换和售后退货不释放用户限兑配额，防止反复兑换。
- 用户限额按用户+兑换商品累计有效兑换件数计算；总配额是运营上限而非第二套实物库存。可兑换数量取可售库存、剩余配额、本人限额的最小值，最终由提交事务裁决。

## 3. 小程序页面与交互

沿用现有UI，首页增加积分商城入口，“我的”增加积分余额、积分明细和兑换订单入口。先采用独立页面，是否增加底部Tab由实际布局决定。

| 页面 | 内容与动作 |
|---|---|
| 积分商城 | 本人余额（游客显示登录查看）、规则入口、分类/搜索、商品图片/规格/所需积分、缺货或已兑完状态 |
| 兑换详情 | 图片、规格选择、整数数量、积分单价/合计、限兑、配送范围、兑换与售后说明；立即兑换 |
| 确认兑换 | 选择本人有效地址、商品快照、现有余额/扣除/剩余、配送说明；确认按钮清楚显示所需积分 |
| 兑换结果与订单 | 待拣货/拣货中/待配送/配送中/已完成/已取消及异常说明；详情、取消申请、售后入口 |
| 积分明细 | 余额、获得/消耗/退还/调整记录、时间、来源订单；游标分页，无数据空态 |
| 售后申请/详情 | 数量、原因、凭证、审批进度、退积分结果；需要退货时展示处理说明 |

每页交付加载、空、失败和重试状态；余额不足显示缺少多少积分，库存不足、规则变化、地址失效分别解释。报价变化须重新确认，不能自动扣更多积分。提交未知时保留幂等键查询原结果，不引导换键重下。游客可浏览，兑换前登录；不展示假余额、虚假兑换人数或销量。

## 4. 后台与作业端

新增独立“积分运营”导航：概览、兑换商品、积分账户/流水、发放审批、兑换订单、售后与规则设置。列表、筛选、详情和表单分开，不把全部功能放一页。

- 商品：从已有名称/规格选SKU；维护标题、积分价、上下架、展示排序、开始结束时间、每人限额及总配额。草稿→上架/下架，价格与规则版本化，历史订单保留快照。真实SKU停用、批次过期/冻结仍阻止兑换。
- 账户：按可授权的用户标识检索，显示余额及来源流水；禁止普通运营导出全量顾客信息。发放与扣减各有审批页、理由、额度校验和审计。
- 订单：订单号、用户、时间、商品、状态筛选，查看扣积分、库存预占、作业与退还证据；不提供任意改状态按钮。
- 权限建议：运营维护商品、申请发放；负责人审批规则与发放；客服处理兑换售后；仓库/骑手维持本仓/本人权限。服务端按动作授权且重新核验员工状态，超级管理员也不得绕过独立审批。
- 仓库与骑手：复用作业页面，明确“积分兑换单”标记；真实积分扣账成功是履约资格，不伪造支付SUCCESS。只在出库时减实物，送达不再扣库存。
- 概览仅统计真实发放、消耗、退还、余额、订单与履约异常；积分兑换不计现金销售额，库存成本单独核算，不把积分当收入。

## 5. 交易、取消与售后

兑换主状态：ACTIVE→COMPLETED，或出库前协调完成后CANCELED；异常单保留原状态和独立异常记录。履约沿用任务状态，售后独立计数；没有支付单。售后完成不抹去原订单及送达事实。

1. 服务端生成短期兑换报价，绑定用户、SKU、积分价、规则版本、数量和地址版本，不扣分不占库存。
2. 提交事务重新检查会话、范围、营业、商品、规则、余额、配额及批次可售；原子写兑换单/快照、积分负流水、余额、库存预占、配额占用、审计、Outbox及幂等结果。全有或全无。
3. Outbox幂等创建真实拣货任务；失败保留待办并补偿，不反复扣分。不能连接合成演练任务作为正式履约。
4. 拣货领取前允许本人取消，事务停止任务、释放预占及配额、退积分；与领取竞争只允许一个合法结果。开始拣货后只能申请，由客服和仓库确认停止；已出库转售后，不自动回库。
5. 首发单SKU缺货建议整单取消并退全部积分，不替换商品。已部分出库不走简单取消，按实物状态处理售后。
6. 售后可按件申请部分退还，按原积分单价×批准数量退款；申请中及已批准数量占用可退额度，并发不能超原兑换数量/积分。驳回或撤销释放申请占用。
7. 授权售后退积分与退款流水同事务，重复请求只入账一次。需要退货时按核验结果处理；退积分本身不增加实物库存，实际退货验收入库单独记录。无须退货的赔付必须留原因。
8. 建立余额对账、积分流水与订单对账、预占与任务对账；差异暂停新增兑换并进入人工核查，不能自动改余额掩盖差异。

## 6. 数据与API设计草案（未实现）

新增 points_accounts（用户唯一、余额、版本）、points_ledger（不可变、有符号整数增量、来源及唯一业务动作键）、points_adjustments（发放/扣减审批与原因）、points_rules（预算及启停、版本）、reward_products（SKU/仓库、积分价、配额、限兑和版本）、reward_user_quotas（用户商品唯一）、redemption_quotes、redemption_orders/items、redemption_refunds。复用审计、幂等和Outbox，地址快照沿用加密规则。

兑换预占必须有外键及唯一来源关联；实际实施前检查现有库存/任务表，增加明确的兑换来源外键或关联表，CHECK确保现金单与兑换单来源恰有一个，不以无外键字符串替代。商品与订单用仓库/SKU复合约束避免错仓。余额非负、积分价正整数、退款总量和配额不超限；账本不可更新/删除。积分BIGINT，API采用十进制字符串防精度丢失，数量仍整数件。

锁序统一为幂等→积分账户→兑换商品/用户配额→按仓库SKU排序的库存余额→订单/退款及任务；所有兑换、取消、退款和出库路径必须核对与既有锁协议的兼容，落地前用并发PG测试验证，不只依赖Redis锁。事务失败回滚，后台重试有界；同键同摘要返回原结果，不同摘要冲突。

建议接口统一前缀 /api/v1，遵循现有响应包裹、会话、CSRF和Idempotency-Key约定：

| 接口 | 权限与作用 |
|---|---|
| GET /rewards、/rewards/:id | 公开可上架商品；不泄露成本/库存批次 |
| GET /consumer/points、/consumer/points/ledger | 仅本人余额/明细 |
| POST /consumer/redemption-quotes | 本人地址、rewardId、quantity；服务端报价 |
| POST /consumer/redemptions | quoteId；同键创建同单，忽略/拒绝客户端积分总额 |
| GET /consumer/redemptions、/:id | 本人列表/详情 |
| POST /consumer/redemptions/:id/cancel、/refund-requests | 本人状态动作，校验版本/原因及售后数量 |
| GET/POST /admin/rewards；POST /admin/rewards/:id/update、/publish、/unpublish | 授权运营及仓库范围；版本校验 |
| GET /admin/points/accounts、/ledger、/adjustments | 权限内用户/流水/审批记录 |
| POST /admin/points/adjustments；POST /:id/submit、/approve、/reject、/cancel | 专用权限，独立审批、幂等入账 |
| GET /admin/redemptions、/:id；POST /:id/approve-cancellation | 本仓订单及协调取消动作 |
| POST /admin/redemption-refunds/:id/approve、/reject、/settle | 售后审批与幂等退积分 |
| GET /admin/points/rules；POST /admin/points/rules/update | 负责人，版本与配置审计 |

上表缩写路径继承所在资源前缀；实施时补齐请求/响应和OpenAPI。分页沿用游标。错误包括 POINTS_INSUFFICIENT、REWARD_UNAVAILABLE、QUOTA_EXCEEDED、STOCK_UNAVAILABLE、QUOTE_CHANGED、ADDRESS_INVALID、VERSION_CONFLICT、IDEMPOTENCY_CONFLICT、INVALID_TRANSITION；不能将失败返回成兑换成功。

只新增迁移，不为老用户批量补积分，不改现金订单历史，不迁移合成单为真单。兑换功能默认关闭；回退先停新增兑换，保留已受理订单的履约/售后处理与流水，不删表回滚事实。OpenAPI在实现后生成，本轮不发布虚假接口契约。
