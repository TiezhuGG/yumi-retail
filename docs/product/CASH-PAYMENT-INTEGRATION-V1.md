# 现金商品微信支付接入路线（2026-11-06）

用户已要求后续支持下单支付。当前现金购物车/报价/未支付订单/库存预占及隔离支付准备已有基础，正式支付模式仍只允许disabled。积分兑换订单与现金支付订单继续独立，不能相互冒充交易结果。本路线将原S5隔离验证接续为正式渠道代码，不再把新增演示场景当作真实支付接入。

| 切片 | 边界 | 状态 |
|---|---|---|
| C1 协议核心 | JSAPI固定下单请求、RSA签名、原始应答验签、同一商户/AppID的小程序支付参数；后台显示进度 | 完成本地验证，非真实下单 |
| C2 支付用户身份 | 微信原始OpenID由服务端安全绑定，明确加密、用途隔离和旧账号补齐；开发身份/subject哈希不得替代 | 完成本地验证，非真实平台验收 |
| C3 渠道下单与恢复 | 私有凭据加载/轮换、真实请求传输、持久化尝试与prepay关联、超时未知和原订单恢复；前端调起只用服务端已验证参数 | 进行中：C3a本地验证完成；C3b下一项 |
| C4 支付入账与取消竞争 | 真实通知/查单验证、金额/商户/AppID/订单绑定、幂等入账、与关单/预占释放互斥、客户端回调后查服务端事实 | 未实现 |
| C5 退款与正式验收 | 真实退款/对账/补偿，商户/HTTPS/真机/资金与实物及生产验收 | 未完成 |

C2/C3可先完成本地代码与隔离验证；实际微信、商户、收费资源、部署和真实资金操作仍需明确授权与准备。小程序/服务器尚未准备，不能报告真实联通或启用支付。

## C3拆分与当前进度

- C3a已实现私有凭据加载/校验、显式轮换、固定地址HTTPS请求、原始应答验签及离线检查；仅用合成凭据和本机TLS服务验收，没有调用微信或接入运行中的订单。见[运维手册](../operations/WECHAT-PAY-CREDENTIALS.md)。
- C3b下一项：真实订单的持久化支付尝试/prepay关联、请求外置、超时/崩溃未知恢复，以及调用前的取消/预占释放保护。当前取消路径仍认为未产生真实支付，不能在其前面直接接通请求层。C3整体未完成。
- C3c后续：凭据/订单模式受控集成、前端仅调起已持久化验证参数及原订单恢复。真实查单/关单与入账竞争仍需C4，真实资金/平台验收仍需C5。

## C1当前约束

- 只生成固定POST https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi的不可变请求；输入来自将来的服务端订单/付款人绑定，不提供前端任意金额、OpenID、签名或URL接口。
- 商户RSA2048私钥只作为KeyObject传入，不从环境、文件或HTTP中读取；受信平台公钥由调用者提供，核心不按响应下载或信任新密钥。实际凭据加载、有效期/轮换及真实归属仍待C3。
- 金额为正整数分/CNY，订单号6至32位允许字符，描述最多127个Unicode码点；商户、AppID和付款人来源必须一致，DEVELOPMENT明确拒绝。格式校验不能证明OpenID属于某一顾客，C2必须提供可信来源；现有consumer_users.subject是不可逆身份哈希。
- 支付期限必须来自原订单，不能延长预占。官方会将不足一分钟的期限调整为一分钟，因此本地在剩余不足60秒时拒绝生成；也拒绝超过15天的期限，不让渠道自动改写。生成的调起参数使用截止时间与自请求构建起2小时中的较早值，秒精度向下取整。
- 应答先做原始字节RSA验签：不区分头名大小写、拒绝重复/数组头、未知公钥、探测签名、非规范Base64、超过正负300秒的时间差和64KiB以上包体，再处理200 JSON中的prepay_id。只输出wx.requestPayment需要的5个参数，不返回付款人或签名私钥。
- 同一核心实例记住已生成请求的引用，拒绝克隆或另一实例的请求，避免误混商户上下文；这只是进程内协议绑定，不是持久化支付尝试、重放防重或财务幂等。微信prepay应答本身不含订单号，未来传输层必须保持请求/响应对应并持久化，后续通知/查单再严格核验交易绑定。
- 没有HTTP发出、wx.requestPayment调用、公开签名接口、凭据保存或已支付写入。任何验签/HTTP异常都不能据此宣布订单已关闭、付款失败或释放库存，后续需按持久化未知结果恢复。
