# 积分商城快递发货首发路线 · 2026-11-03

用户最新明确要求：积分兑换商品、产生订单、后台打印订单、人工交快递发货；沿用既有UI风格，由Codex自主设计实施。原小区仓配/骑手设计与代码保留作扩展，不删除事实、迁移或历史验收；暂停P4j等原路线后续任务，不再作为本次快递首发的必经操作。

[原路线完整快照](POINTS-MALL-LOCAL-DELIVERY-ARCHIVE-2026-11-03.md)。现有P1账户、发放/冲正、商品、积分扣账、订单、库存预占与交易约束继续复用。现有订单属于原小区地址/自配送模式，不得改文案冒充已支持快递。

## 首发流程

选择兑换商品 → 核实快递收货地址与积分合计 → 提交扣分/预占并生成待发货订单 → 后台单张或批量打印配货单 → 人工打包寄快递 → 填快递公司/运单号确认发货 → 用户查看发货资料。订单打印不等于发货，也不等于快递电子面单。

暂不对接快递账号、电子面单或自动物流轨迹；暂不做拆单、多包裹、多次发货。运费收取/包邮方案、可寄范围、正式积分经营参数仍需配置确认，不自动开启现金支付、全国发货或生产交易。

## E1实施约定

使用现有授权运营/负责人points.read和本仓范围；新POST /admin/redemptions/print-preview（Origin/CSRF），仅允许当前有效订单，1–20个不同订单号来源ID，服务端一次性验证全部归属、状态、当前会话后解密原订单地址快照；混入越权/取消/不存在单整批拒绝，不泄露部分地址。按请求顺序返回最小配货字段，不返回消费者身份、密文、内部流水或历史人员信息。普通列表仍无完整收件信息。

预览与打印触发前分别重新读取服务器，禁止用浏览器缓存地址直接长期重打；预览仅内存，关闭/切换/失权清理。浏览器打印使用隔离同源空白iframe，以DOM textContent写入数据，避免把备注当HTML执行；A4每单分页，支持重复打印但不记“打印成功”、不改变订单/库存/积分/待办。取消单须拒绝；预览以后若取消，实际打印前再次校验拒绝。打印页注明真实配送方式、配货单非面单、打印时间，保留商品/规格/件数/积分及收件人地址/备注。无数据库迁移。

E1可对旧单提供配货打印；快递收货及发货尚需E2/E3，不将E1标为快递交易上线。
