# 产品需求与经营规则 V1.1

状态：设计基线及已实施切片记录。用户确认范围与开发默认规则分开记录。更新：2026-10-28。

## 1. 用户确认与业务假设

已确认：单小区、单仓；保留仓库与骑手系统；暂无生鲜；负责人 + AI 研发，追求性价比、速度和质量。

首版建议销售常温、固定包装、固定售价、按件/袋/瓶/箱等整数单位售卖的普通商品。是否含预包装食品、冷冻品、酒类未确认，不能自动纳入经营范围。有保质期的商品仍需要批次效期。

以下默认参数用于设计和开发样例，正式运营前必须配置并核验：

| 参数 | 建议开发默认值 | 说明 |
|---|---|---|
| 服务小区 | “演示小区” | 正式名称、楼栋白名单待提供 |
| 营业时间 | 08:00–22:00，Asia/Shanghai | 支持暂停接单与特殊营业日；不是正式对外承诺 |
| 起送金额 | 商品合计 2000 分 | 不含运费；首期无优惠 |
| 配送费 | 每单 300 分 | 首期固定，不实现满额免运或距离计费 |
| 付款时限 | 15 分钟 | 使用服务端时间；超时触发查单/关单流程 |
| 报价有效期 | 2 分钟 | 报价不锁库存；提交时重新校验 |
| 每单 SKU / 件数 | 50 / 200 | 建议技术保护上限，可配置 |
| 履约承诺 | 显示营业与配送说明 | 不显示未经运营验证的“30 分钟必达” |
| 售后政策 | 人工审核与原路退款 | 申请窗口、证据要求及法定保障需按实际品类核验 |

## 2. 角色与业务权限

| 角色 | 可做 | 数据范围 |
|---|---|---|
| 游客 | 浏览、搜索、本地购物车 | 公开商品与店铺信息 |
| 消费者 | 地址、报价、支付、订单、售后 | 本人资源；每次接口检查归属 |
| 负责人 / 超级管理员 | 员工、配置、商品、仓储、订单、退款、对账 | 当前经营主体及仓库 |
| 运营 | 商品、分类、推荐、订单查询 | 配置范围；无默认退款/权限管理权 |
| 仓管 | 入库、库位、批次、盘点、报损 | 被授权仓库 |
| 拣货员 | 领取、拣货、缺货上报、打包出库 | 本仓作业任务；不审批退款 |
| 调度人员 | 分配、撤回、重新分配配送任务 | 本仓待配送任务 |
| 骑手 | 接单、开始配送、送达、上报异常 | 当前分配给本人的任务；履约后隐藏非必要联系方式 |
| 客服 / 售后 | 查看相关订单、审核申请 | 按授权；高金额/退款执行权限独立配置 |

角色可合并分配给同一员工，但记录操作时不能只写“系统”。仓管权限不自动包含退款，骑手不应拥有后台全局订单查询权限。

## 3. 商品与销售规则

- B01：SPU 表示商品概念，SKU 表示唯一售卖规格；即使首期每个商品只有一个 SKU，仍保留两层。销售单位不自动换算，整箱和单瓶若作为两个 SKU，不能凭空共用库存。
- B02：SKU 维护内部编码、可选条码、规格、单位、售价、上下架、效期管理标识及图片。价格为人民币整数分且大于零，数量为正整数。
- B03：首版不包含优惠券、会员、积分、满减、动态促销、预售、称重和替换商品差价。商品当前价格不能更改历史订单快照。
- B04：草稿、下架、缺货、过期不可售商品不能下单；已下单有效预占不因普通下架自动失效。已付订单仍需正常履约或走异常退款。
- B05：分类最多两级；含商品或子分类的分类只能停用/迁移，不能直接删掉引用。
- B06：商品图片和详情须对应实际商品；首版不展示无真实来源的月售、评分、划线价或资质。

## 4. 服务范围、账户与地址

- B07：浏览无需强制微信登录或定位。用户进入需选择/确认服务小区，单小区也要清晰显示范围。
- B08：结算需要业务登录；微信登录凭证由服务端交换身份，消费者不接触 AppSecret 或微信 session_key。手机号作为联系资料单独填写和校验，不与登录身份混淆。
- B09：地址由小区、楼栋、单元、房号、联系人、联系电话、详细说明组成。服务端按有效小区与楼栋校验，不仅校验前端下拉值。
- B10：更改默认地址在事务中保证单用户唯一默认；删除地址不改历史订单快照。
- B11：首版已提交订单不直接更换收货地址，需取消重下或客服按受控流程处理；配送中修改地址不开放。备注不能改变配送范围或价格。
- B12：消费者仅能读取本人地址、订单、退款、图片附件；猜测到 ID 也不能绕过权限。

## 5. 购物车、报价和下单

- B13：游客购物车保存在本地；登录后按 SKU 合并，数量取原数量相加并受单次限额限制，返回失效/超量项，不静默丢失。购物车不占库存。
- B14：报价输入地址和所选 SKU 数量，服务端检查商品状态、库存、范围、营业、起送和上限；返回逐行金额、运费、合计、报价版本和到期时间。
- B15：金额公式：`商品金额 = Σ(单价分 × 数量)`；`应付 = 商品金额 + 运费`。首版优惠为零。开发统一示例：900+590+1680=3170，运费300，应付3470。
- B16：报价不承诺锁价锁库存。提交订单时锁定相关库存行，重新验证商品/价格/地址/规则；发生变化返回明确冲突与新报价，用户再次确认，不能擅自按更高金额扣款。
- B17：每次购买意图使用 Idempotency-Key，网络重试保留该键；服务端绑定用户、操作和请求摘要。相同键同请求返回同一订单，不同请求内容返回冲突。
- B18：订单、订单快照、库存预占、幂等结果与待执行事件同事务提交；某一商品不足则整单失败，不留下部分预占。提交后才调用外部微信支付预下单。
- B19：订单创建时间与付款截止时间由服务端生成。小程序切后台、关闭页面或点击取消支付均不直接取消业务订单。

## 6. 订单、支付与取消

以独立维度记录，不使用一个状态枚举覆盖所有场景：

| 维度 | 状态 |
|---|---|
| 订单主状态 | AWAITING_PAYMENT / ACTIVE / COMPLETED / CANCELED / EXCEPTION |
| 支付单 | NOT_STARTED / PENDING / SUCCESS / CLOSED / UNKNOWN |
| 履约 | NOT_READY / READY_TO_PICK / PICKING / PACKED / READY_TO_DELIVER / DELIVERING / DELIVERED / EXCEPTION / STOPPED |
| 售后申请 | REQUESTED / APPROVED / REJECTED / PROCESSING / SUCCEEDED / FAILED / MANUAL_REVIEW |

`UNKNOWN` 表示渠道结果不确定，不能当作失败；取消处理中用独立取消请求记录，不强塞为付款失败。售后失败保留历史，订单可继续存在。

- B20：业务支付成功仅由已验签校验的渠道通知或主动查单确认。核验商户、AppID、商户订单号、金额、币种及付款身份；前端回调不直接记账。
- B21：付款成功事务将订单置 ACTIVE、支付置 SUCCESS，记录流水并创建履约待办事件；重复通知不重复扣库存、不重复产生任务。
- B22：超时先主动查单；未支付则请求渠道关单；只有确认不可继续支付后，才能在同一事务取消订单并释放预占。渠道不可达则保持预占、标记待核实并重试/告警。
- B23：已支付订单不执行“关单即退款”。建议首期：拣货前消费者可申请整单取消；客服批准后停止作业、发起包含运费的全额原路退款。拣货中或已出库由客服协调，不自动撤销配送。
- B24：晚到支付与超时任务竞争时锁定同一订单，支付成功不得被普通取消覆盖。若发生已释放却证实已支付的异常，保留资金记录，尝试重新预占；失败转异常与退款，不无货放单。
- B25：付款失败/取消可在订单有效期内重新调起同一支付单；结果未知先查单。关闭的支付单不重开，已取消订单重新购买产生新订单。

## 7. 轻量仓库系统

### 7.1 必须的作业

| 作业 | 首版行为 | 完成证据 |
|---|---|---|
| 仓库与库位 | 一个仓库，多个库位；默认收货位与不可售区 | 所有库存行可追溯仓库/库位 |
| 收货入库 | 草稿→确认收货→过账；记录来源、SKU、批次、数量、成本、效期（适用时） | 一次过账一次库存增加及流水 |
| 上架/移位 | 同仓库位移动，汇总实物不变 | 成对明细流水且事务一致 |
| 盘点 | 指定 SKU/库位短时冻结移动，记录账面、实盘、差异与审核 | 差异单过账后数量可核对 |
| 报损 | 指定批次/库位、原因、证据及数量，审批后过账 | 不可负库存；保留损耗成本 |
| 拣货 | 支付确认后创建任务，领取锁定，按已分配批次逐项核对 | 操作者、实拣、缺货可追踪 |
| 打包出库 | 全部明细完成/已处理缺货后确认，事务减少实物与预占 | 一单仅一次有效出库 |
| 退货回库 | 验收实物后独立入库，区分可售与不可售 | 不由退款结果自动触发 |

### 7.2 库存口径

`实物 on_hand` 为账面在库数量，含被预占与不可售数量；`blocked` 为不可售数量；`reserved` 为订单占用；`safety` 为运营保留量。`可售 = max(0, on_hand - blocked - reserved - safety)`。

聚合库存与批次库位明细必须在同一事务更新；可售批次须未过期且符合效期阈值。商品启用效期管理时入库必填生产/到期信息和批次；无效期商品仍记录入库批次。按近效期先出，其他按先进先出分配。过期/隔离库存不可继续销售。

库存调整、报损或过期处理若涉及已被预占数量，不能强行减成负数；先冻结相关销售并进入订单异常处理，解除或重新分配受影响预占。盘点期间提交订单或出库遇到冻结行必须得到明确提示和可重试结果。

### 7.3 缺货策略

首版不自动替换商品、不额外向顾客补收费用。缺货由仓库上报，客服联系顾客并记录处理选择：

1. 继续配送其余商品：取消缺货行的未出库预占，创建对应售后申请；按该行历史金额退款，不因缺货后低于起送重新加价；原运费不变。
2. 全部取消：未出库则停止任务、释放剩余预占，包含运费整单退款；已出库需先处理拦截/退回实物。
3. 顾客暂未联系到：保持任务异常，不擅自少发、不假记送达；待负责人处理。

缺货方案确认后才能出库；允许退款处于渠道处理中，但该行必须已被正式取消、退款义务已持久化且有补偿任务，不能仅在备注里写“稍后退钱”。

## 8. 骑手配送系统

- B26：打包出库后进入待配送队列，调度人工分配给有效骑手；任务接受前可撤回重分配，保留历史。每笔订单同时只允许一个有效配送任务。
- B27：骑手端仅显示本人任务。接单和开始配送均校验当前指派与版本；重分配后旧骑手请求必须失败。
- B28：正常流转：待分配→待接单→已接单→配送中→已送达。未接单/拒接可以回到待分配；配送中不能直接重派，需异常协调。
- B29：开始配送检查订单已支付、已出库、未停止；骑手送达只改变履约状态，不再次扣库存。
- B30：送达需确认操作并记录操作者、时间和证明方式。建议首版采用骑手确认+可选照片/备注；照片私有存储且不强制拍摄住户隐私。是否必须签收码待运营决定。
- B31：无法联系、地址异常、破损、拒收等进入异常，填写原因；调度可记录重新配送、退回、退款。送达后的纠错由授权人员走异常更正，不开放任意回退。
- B32：无后台持续定位，不显示实时轨迹、距离和虚假预计到达时间。骑手拨号与收货信息访问记录审计，任务完成后按权限最小化展示。

## 9. 售后与退款

- B33：申请指向订单行、数量、原因和可选凭证；金额由服务端生成。审核/退款不能按商品当前价格计算。
- B34：提交时锁定订单退款额度，预留“申请中+审批通过+渠道处理中”的金额与数量，防止并发申请超退。拒绝、撤回或在确认渠道未退款后正式终止申请，才解除额度；渠道失败但商家仍有退款义务时继续占用并补偿，未知状态也继续占用。
- B35：商品行可退上限=该行原实付−该行已退−有效待退；整单可退上限=原实付−已成功退款−有效待退，运费作为独立额度管理。
- B36：首期无优惠所以行实付=单价×数量。以后增加优惠必须先实现逐行分摊、尾差规则与退款分摊，不能直接加前端优惠字段。
- B37：建议未履约整单取消退全部商品与运费；部分缺货退缺货商品，不追加运费；配送完成后的质量/服务争议由客服按政策决定商品与运费退款。正式政策需业务确认与核验。
- B38：审核通过→持久化退款指令→渠道受理→查单/通知确认成功。接口超时不能重新生成新的退款业务号去重退；始终使用同一商户退款号查询/重试。
- B39：退款与实物流独立。未出库取消只释放预占；已出库退回必须实际验收后做退货入库；无实物退回的退款不加库存。
- B40：售后详情展示审查、退款处理中、成功/失败及原因；审核通过不显示为“已到账”。

## 10. 通知、统计和运营

首版以后台工作队列+页面刷新/轮询保证待办可见，订阅消息为后续优化，不以用户授权通知作为订单成功前提。订单状态、资金状态不依赖通知是否送达。

统计按北京时间自然日：支付金额按 payment.success_at 计，退款按 refund.success_at 计；净收款=本期支付−本期成功退款；支付客单价=本期支付金额/本期成功支付订单数（无订单时显示0）；经营分析不可把净收款当利润。库存成本未验证前不提供毛利结论。账单手续费与结算到账另行核对，不混入消费者实付金额。

核心运营指标：支付成功率、未核实支付数、超时未拣/未接单/未送达数、账实差异、缺货率、退款失败数、渠道对账差异和系统错误率。

## 11. 必须验证的业务场景

| 场景 | 预期 |
|---|---|
| 最后一件商品多人下单 | 仅一个有效预占，不超卖 |
| 连点提交/网络重试 | 相同意图只有一张订单 |
| 改价后提交旧报价 | 冲突并展示新报价，不静默加价 |
| 前端取消但渠道实际扣款 | 主动查单恢复成功，不丢订单 |
| 支付回调与关单同时发生 | 状态和资金一致，预占不误释放 |
| 服务重启/重复回调 | 作业和资金记录不重建、不重复扣减 |
| 盘点/报损撞上预占和出库 | 不负库存，冲突可解释 |
| 拣货缺少一件 | 联系记录、行取消、退款义务和出库数量一致 |
| 骑手重新分配后旧端操作 | 返回无权限/版本冲突 |
| 两人同时申请/执行退款 | 不超数量、不超金额、单一渠道退款号 |
| 退款后无退货 | 库存保持不变 |
| 断网后骑手重复送达 | 首次成功，其后幂等，无重复库存动作 |

## 13. S1员工登录切片（2026-10-27）

后台与移动作业端使用员工账号密码登录，可刷新恢复会话、查看当前角色与授权仓库、退出当前设备会话。角色在服务端固定，管理员也不能任意跨仓；骑手不具备仓库管理权限。账号停用、会话撤销/到期或auth_version变更后下一次请求拒绝；角色与仓库范围变更下一次请求生效。当前只提供只读员工列表，没有员工创建、改密、授权管理页面或配送业务。

## 14. 商品与收货切片（2026-10-27实施边界）

## 15. 库位与账本核对（2026-10-27增量）

本节覆盖第14节“固定DEFAULT货位”的历史限制。当前已有真实普通存储库位、批次位置及位置流水；新仓自动有DEFAULT默认收货位，新收货先入DEFAULT，再通过专用同仓移位动作整理。每个批次可在多个普通库位分布；跨仓调拨、隔离区转换与直接修改库存数量仍未提供。

库位代码在仓内唯一，普通库位可创建、启停；有实物/预占/blocked的库位不得停用，DEFAULT不得停用。移位指定源位置、目标库位、整数件数、源版本及原因，只移动未blocked数量；源位置有任何预占时首期整位置拒绝移位。过期批次允许实物移位，但不会因此恢复可售。移位一次性过账、重复意图不重复移动，仓库/批次总量不变，位置记录一减一加。

核对针对一个SKU检查汇总、批次、位置及两级流水，保存不可改报告。发现差异设置inventory_hold，公开可售为0，入库与移位拒绝；核对不自动修数，也不改变SKU上下架。差额相抵仍通过逐位置流水比较发现。重新核对一致也不自动解除暂停；管理员/仓管须明确提交原因与余额版本，服务端再次完整核对后才解除核对暂停。

报告只展示前100项差异并保留完整差异数量。当前是人工按SKU核对，无全仓定时任务/外部告警派发；“账本一致”不是实物盘点一致，也不是已完成订单预占校验（订单尚未实现）。账本差异须按证据调查与逆向纠错处理，不能用盘点或报损掩盖；实物差异使用盘点，已隔离货品使用报损，禁止通过SQL直接改数模拟业务处理。测试中的故障注入与恢复仅在一次性schema进行。

管理员/仓管可管理库位、移位、核对及带证据解除核对暂停；拣货员仅看无成本的库位/批次/位置流水与报告，不能执行这些写操作；骑手不得访问仓储。经营分权、实物验收和完整仓储仍待后续确认/开发。

## 16. 实物盘点（2026-10-28实施增量）

单仓单SKU全位置盘点：FROZEN→SUBMITTED→APPROVED→POSTED，前三种状态可提交原因转CANCELLED。最多200个已有位置，超过上限拒绝，不能截取部分位置作为完整盘点。开始前库存版本须匹配、账本一致、无核对暂停及预占；记录每位置账面/预占/不可售数和位置版本，冻结该SKU销售、收货、移位。无自动超时解冻；负责人须在实物作业结束后过账或明确终止。

开发默认分权：管理员/仓管可发起，仅发起人一次提交全部位置的实盘整数件数；另一位具审批权限的员工填写意见审核，发起人不得自审。具过账权限的员工执行过账。正式人员安排/阈值尚待业务确认。提交后不可更改实盘；需纠正时终止重建，已过账不可取消或删改。

实盘数含blocked，不得低于预占+blocked；过期批次仍不可售。审批/过账重新检查快照及账本，不覆盖版本变化。差异新建主流水及位置流水，同事务修改位置/批次/汇总缓存、单据、审计和幂等结果。零差异不新增数量流水。冻结指针只在过账/终止时同事务释放，不清除独立的inventory_hold；终止时发现新的账本差异会保存核对报告并设置核对暂停，避免异常恢复销售。

该盘点切片不处理未知批次/未知位置盘盈、成本重估、多SKU盘点、实物隔离转换或订单预占/出库；数量隔离/报损由下节独立切片实现。实盘数来自合成测试，不代表经营者已经完成真实仓库验收。

## 2026-10-28 数量隔离、解除与报损开发规则

已实现本地切片：问题库存先在原库位按数量隔离，立即增加不可售blocked，实物数量不变。管理员/仓管可执行；解除/报损须另一位员工独立审批后过账。解除只减blocked；报损同时减onHand与blocked，须明确核验实物并记录说明。无实物系统联动，技术测试不证明现实处置已经完成。

申请DRAFT→APPROVED→POSTED，过账前可带原因取消，取消不解除隔离。草稿不预扣隔离剩余额度，最终以串行过账及版本复核为准；旧快照取消重建。只处置指定隔离记录的remaining，不扣预占、不消费其他隔离或历史blocked。过期/停用库位拒绝解除，可隔离及报损；盘点冻结/核对暂停/账本不一致拒绝数量动作。当前是原库位数量隔离，实体隔离区移位、供应商退货、自动效期任务另行开发。

这些是开发默认规则，真实员工分权、实物核验SOP和损耗财务口径仍待负责人确认。

## 2026-10-28 收货逆向纠错开发规则

本节覆盖此前“已过账逆向待实现”的限制。每单关联原已过账批次的一个库存位置，可部分冲回误录数量；原收货保持POSTED，原行、成本及原流水不可改删，正确资料另建正常收货。管理员/仓管申请、取消、过账，另一员工独立审批；DRAFT→APPROVED→POSTED，前两态可带原因取消。过账须确认原记录与实物误录核验并说明。草稿不预扣额度，取消不改数；正式岗位与SOP仍待负责人确认。

累计已冲回不得超过原收货行数量，盘盈不增加额度。只能扣原批次当前位置自由数onHand−reserved−blocked；预占、隔离及隔离剩余不变。移位后仍追溯原批次；跨位置分单，不用其他批次补足。审批/过账重新检查位置版本、冻结/核对暂停、账本一致及原额度；旧快照取消重建。过期/停用位置可纠错，不恢复销售资格。多录可部分冲减；错SKU/批次/成本等仅在可完整冲回时通过逆向与新收货分别留痕纠正；已消费或受保护部分不强制回退。

当前不提供供应商退货、财务冲账、退款、整单多批次自动撤销或修改历史数据；不能用逆向纠错掩盖账本不一致。
