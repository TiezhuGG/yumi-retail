# 积分快递本地冷备份恢复演练

范围：Windows 本机、PostgreSQL **17.11**、合成账户/积分/库存及随机独立集群。不是现有开发库的备份工具，不接受数据库连接地址、已有数据目录或远程目标。现有 `.env`、开发库和测试库均不加载、不迁移、不覆盖。

## 运行

使用项目锁定的 Node 24.22.1，先准备已有本地工具包 `.local/pg-tools/node_modules/@embedded-postgres/windows-x64`，精确版本 `17.11.0-beta.19`；工具核对服务器版本 17.11，不自动下载或安装其他版本。

```powershell
npm run test:express:recovery
$env:YUMI_LOCAL_RECOVERY = '1'
try { npm run verify:express:recovery } finally { Remove-Item Env:YUMI_LOCAL_RECOVERY }
```

命令先构建 API/数据库包，再创建 `.local/express-recovery-随机值`。该目录中的数据库密码和资料全部为临时合成数据；成功或检查失败后关闭自建集群并清理自有目录。停止集群或清理失败时不强删正在运行的目录，保留现场由本机负责人处理。脚本不调用现有 PostgreSQL 服务的启动/停止命令。

## 验收事实

1. 独立实例创建全量迁移、合成微信主体及受控订单：待发货、已发货并留痕纠错、已取消；已发货订单带加密反馈。全部交易走实际 API 和 PostgreSQL，微信主体本身由隔离测试夹具合成。
2. 记录每张表逐行排序后的内容摘要和行数，关闭全部夹具 API/连接，使用 `pg_ctl stop -m fast -w` 停止自建源集群；确认进程状态为未运行且 PID 文件不存在。
3. 复制整个已停库目录到新备份目录，包含 WAL/事务提交信息。逐个文件核对长度、SHA-256，再从备份复制到另一恢复目录并复核。拒绝符号链接/目录联接及特殊文件，不支持外部表空间。
4. 同一台机器、同一二进制从新恢复目录启动，源目录保持停止。API 启动前逐张表核对所有原始行摘要，不能仅以表数或 HTTP200 通过。
5. 错误加密密钥时地址/反馈读取必须失败；恢复单独保存在内存中的合成密钥副本后，地址/反馈原文、订单模式、运单更正及原发货时间必须一致。这验证密钥匹配依赖，不证明外部密钥托管已经建立。
6. 新兑换/作业保持暂停，原成功创建、发货、纠错、反馈、取消的请求键仍能核实原结果；临时允许合成作业后，另一订单占用历史原运单/更正运单分别被拒绝，再次暂停。除认证会话活动时间外，所有业务表逐行摘要不变。首发检查差异为零、无骑手任务、canLaunch=false。

结果只写入忽略的 `.local/express-recovery-report.json`，不包含数据库地址、密码、密钥、收件资料、反馈全文或用户 ID。失败不产生本轮成功报告；使用时须核对报告时间与本轮命令退出码，不能用旧报告代替。

## 适用限制与部署接续

采用[PostgreSQL 17 完整停库文件备份要求](https://www.postgresql.org/docs/17/backup-file.html)，不是在线复制、SQL 导出或 PITR。恢复计时只是本机合成样本操作耗时，不是生产 RPO/RTO。生产的操作系统、PG 版本、托管服务、表空间、备份介质和密钥系统都尚未选定，不能直接套用该脚本。

真实测试环境到位后：先填[受控配置模板](points-express.controlled.env.example)，保持提交/作业开关均为0；核实隔离数据库、HTTPS、微信工程 AppID 和运营账号；执行只读配置预检；在环境自身支持的新隔离目标上完成实际备份及合法密钥副本恢复；核对匹配产物/迁移后，按[首发手册](POINTS-EXPRESS-LAUNCH-RUNBOOK.md)执行有授权的部署和工具/真机、打印机、交快递验收。本机冷备不替代该步骤。没有测试服务器/域名时不标记真实联调通过，也不开放生产。
