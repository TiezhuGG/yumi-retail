# 积分商城首发全流程回归

使用「积分商城」分支、真实本机 PostgreSQL 随机 schema、合成顾客与实际 API。微信凭证由测试专用适配器返回。浏览器适配小程序组件并记录页面导航，后台运行实际页面组件。

| 场景 | 本地结果 |
| --- | --- |
| 小程序首页与登录 | 从首页商品卡进入详情，点立即兑换，确认页要求登录。登录返回后使用原商品与数量进入确认页 |
| 门禁和下单恢复 | 暂停、名单限制、读取失败及报价后暂停均验证。恢复提交后故意丢失已成功的响应，刷新后用原请求恢复 |
| 扣分、打印和发货 | 受控账号从 1000 积分降至 880，只有一笔兑换。后台先查看 A4 配货单，再填写运单并确认发货。用户可查同一运单 |
| 售后 | 同一订单由用户提交反馈，运营回复并结束，用户查看结果 |
| 作业隔离 | 暂停作业时发货被禁用。正式受控环境中的开发单无法发货。受控订单仅一条发货事实，无骑手拣货任务 |

浏览器复验通过并保存 16 张截图。示例包括[首页](UI-POINTS-LAUNCH-MINI-LAUNCH-HOME-2026-11-04.png)、[发货前配货单](UI-POINTS-LAUNCH-ADMIN-LAUNCH-PRINT-BEFORE-SHIP-2026-11-04.png)和[运单及售后回复](UI-POINTS-LAUNCH-MINI-LAUNCH-FEEDBACK-CLOSED-2026-11-04.png)。首轮浏览器执行超时，复验通过，保留更短的诊断超时以显示原始错误。

本机发布报告 `.local/express-release-report.json` 检查通过，API 0.59.0，小程序为本地构建，`canLaunch=false`。

数据库首轮 44 项有一项旧小区配送兑换创建返回 500，单项复验通过。串行完整复验包含微信身份与受控门禁，共 51 项全部通过，旧配送异常未复现，原因尚未确认。

小程序构建与发布保护等 9 项检查通过，根测试类型检查、脚本 ESLint、Prettier 和 Git 差异检查通过。后续可通过 `npm run test:express:regression` 复跑含微信身份和受控门禁在内的数据库套件，通过 `npm run verify:points-express-gate:ui` 复跑浏览器流程，浏览器运行需要现有本机 UI 验证配置。

真实受控验收仍需隔离 HTTPS 地址、真实小程序 AppID 和服务端配置、测试人员和商品、可用打印机及实物快递。真机验收时需确认请求域名校验开启。本机工程私有配置目前 `urlCheck=false`，小程序默认工程 AppID 为占位值。实际经营还需确认积分发放、寄送范围、运费和人工售后安排。按[受控环境手册](../operations/POINTS-EXPRESS-CONTROLLED-ENVIRONMENT.md)核对环境备份与密钥恢复、微信、真机和实际快递。
