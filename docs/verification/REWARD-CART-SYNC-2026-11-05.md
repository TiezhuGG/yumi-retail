# 积分账号购物车服务端保存（2026-11-05）

范围：本人积分购物车服务端保存、旧设备商品明确导入、并发/换号/未知请求保护、兑换后同事务扣减。验收案例为两个独立浏览器上下文读取同一账号、A/B换号、冲突不覆盖、弱网重试不重复合并、购物车兑换失败全部回滚及成功仅清理已购数量。现金支付与合并主订单不在本轮范围。

## 实际行为

- 登录后购物车商品与整数数量存PostgreSQL，独立于原现金SKU购物车；重新进入读取最新快照，无实时推送。游客仍保存在本机。购物车勾选保持页面本地状态。
- 保留旧按账号本机商品和游客商品，各自明确点击导入后才累加；不静默迁移、不跨账号导入。失效条目保留供删除，不占库存或积分，价格和库存以实际商品查询/结算核验为准。
- 修改使用版本校验、行锁和持久化幂等请求。另一设备更新时提示重新读取；保存未知时恢复原请求并读取最新版本，防止使用重放结果覆盖另一设备后续修改。
- 游客未决导入记录绑定原账号，另一账号不能再次导入；加购结果未知时，详情页再次加购被阻止，提供“查看购物车”核实入口。本机导入扣减与完成标记一次写入，避免响应重试重复清理。
- 新购物车兑换传consumeCart=true，在原扣分/预占/订单事务中扣减当前购物车已购数量，保留期间新增数量；同键重复提交不再扣减，任何失败连同购物车一起回滚。直接兑换保留购物车。
- 旧checkout intent没有cloudCart标记，保持原请求摘要和本机扣减流程；不把升级前已受理但未收到结果的订单变成新下单。无经营配额恢复。

## 模型、兼容性与本地更新

OpenAPI 0.64.0，新增GET/POST /consumer/points-cart及购物车订单可选consumeCart字段。迁移202611050004_reward_carts新增购物车及不可变操作审计表，使用本人身份，不提供客户端userId选择。

先以私有权限备份本地开发库，再应用第60项迁移。112张原业务表逐表行数/完整行摘要均不变，新增购物车表为空；没有迁移/创建真实顾客购物车，也没有下真实订单。迁移报告位于`.local/reward-cart-migration-report.json`，备份保留在`.local/backups/`，不提交备份或任何凭据。API已核验原进程归属后重启，小程序普通构建已重编译；开发顾客A/B入口仍关闭。

部署顺序：先数据库和兼容API，再小程序。旧客户端的本机方案可继续运行，后续升级明确导入；不回滚已写入的新表后继续使用新客户端。未执行生产部署或外部连接。
