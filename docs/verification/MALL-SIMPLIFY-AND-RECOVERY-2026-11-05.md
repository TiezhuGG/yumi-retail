# 商城样式恢复、页面精简与取消限额（2026-11-05）

## 原因与恢复

上一轮源码已修改，但整理样式时误将 app.less 覆盖成账户页组件内容，导致格式/编译失败，微信仍使用旧产物。恢复尝试因可能覆盖未提交UI内容被自动审查拒绝。本轮先保留误写现场到 `.local/style-recovery/app.less.overwritten`，将Git样式候选用Less编译并与此前实际渲染的完整CSS逐字比对，确认一致且包含原购物车样式后，安全恢复原样式，补回已知订单加载和商品按钮布局。不是丢弃现有界面重做。

## 最终变更

- 商品详情标题改“商品详情”，采用普通商品的图片、名称、积分价、规格、数量、合计和底部操作。去掉限额展示；“加入购物车”和“立即兑换”均固定高度并水平/垂直居中。
- 购物车、订单和我的删除顶部标语及重复解释；我的服务行、订单模块及底部也去掉冗余说明，保留真实积分、状态、功能入口、错误/空状态和用户主动展开的规则。
- 订单原生下拉刷新、上滑到底部自动分页保留；移除手动刷新/加载更多按钮，读取失败可重试。
- 按用户“不用限额”的要求，取消实际每人累计及商品总配额限制，前后端均不再按旧配额算 available；只按实际可售库存与积分校验兑换。商城卡片和后台表单同步去掉限兑文案/配置。
- 新增第59项迁移，只删除限额专用触发器/函数；历史字段和现有业务数据保留，API0.62.0标记字段deprecated。所有库存、扣分、订单与售后一致性约束继续工作。

对照负责人提供的三张截图核查：订单页“玉米百货 · 积分商城”、购物车两行介绍在源码中已删除，本轮再次检查编译产物实际渲染，确保不再输出；登录页介绍也删除。原“账号设置”仅展开隐私、退出及失效会话清理，并无头像/昵称编辑功能，现移除折叠入口，将这些明确操作直接放在常用服务中，登录按钮简化为“微信登录”。
