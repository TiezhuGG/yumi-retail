# S2 单SKU实物盘点交付 · 2026-10-28

本机可审查切片完成：冻结快照→发起人录入提交→另一员工审批→差异过账并解冻；未过账可带原因终止。管理员后台与移动作业页共享操作。正式经营分权、真实仓库实盘和微信真机仍未验收；不是可交易上线版本。

## 实现及业务边界

- 一个授权仓库/SKU、全部已有位置，1–200行；200完整快照通过、201拒绝，不静默漏位。冻结前版本匹配、账本一致、无预占和核对暂停。
- FROZEN→SUBMITTED→APPROVED→POSTED，前三态可CANCELLED。仅发起人提交完整实盘结果，另一员工审批；三项权限count.write/approve/post只授予管理员/仓管，拣货员只读、骑手拒绝。此分权为开发默认，正式运营待确认。
- 全过程使用余额行锁、仓库授权、版本、持久化幂等、审计；同键不同内容冲突，同键重试返回原结果。冻结公开可售0，拒绝收货/移位；数据库也保护冻结中的余额、批次和位置数量。
- 实盘含不可售，不能低于预占+blocked；提交后不可改。复核快照与账本，发现冲突保留冻结供排查/终止。盘盈盘亏创建新COUNT主流水/位置流水，不改历史事实。零差异不制造数量流水。位置与批次先减后加，汇总按净差额更新，数量上限10亿件。
- 数量缓存、流水、单据、审计、幂等结果和解冻同事务。终止不改数量，不清除独立核对暂停；终止时新发现账本差异会保存报告并设置核对暂停，公开仍0。
- 无自动超时解冻，须负责人确认实物作业结束后过账/终止。暂不支持多SKU、未知批次/未知位置盘盈、成本重估、报损、隔离转换、已过账逆向纠错。盘盈保留已有批次成本来源，不能据此声明成本会计已完成。

## 本机演示

1. 启动Docker Desktop，执行`npm run db:up`。停止旧版项目API/Worker后执行`npm run db:generate`、`npm run db:migrate`、`npm run db:migrate:test`、`npm run db:seed`；需要合成商品时执行`npm run db:seed:catalog`，重复执行不会重复入库。
2. 分别运行`npm run dev:api`、`npm run dev:admin`、`npm run dev:ops`，打开127.0.0.1:5173/5174。账号仅在本机忽略的.env，使用LOCAL_ADMIN或LOCAL_WAREHOUSE对应账号，勿公开凭据。
3. 在库存位置复制规格ID，到“实物盘点”填写原因并开始；账面库存显示冻结单号，公开products/:skuId可售0。不要对真实备货填入虚构实盘数。
4. 由发起人填写每个位置的完整整数实盘数并提交，页面显示差异；退出后另一位有同仓权限的员工登录，查看该单，填写审批意见并审核。
5. 过账后应自动刷新汇总及位置，公开可售依据新库存/效期/安全量重算；位置流水可见COUNT:单号:行号。也可在未过账状态填写终止原因，验证数量不变、盘点冻结释放。核对暂停仍须独立复核解除。
6. `npm run test:counts`可重演全部盘点HTTP/数据库案例；`test:inventory`、`test:s2`、`test:s1`、`test:s0`是原功能回归。不要把S0的validation_竞争探针当成正式订单功能。

## 迁移与回退

新增单据/快照两表、余额active_count_id及复合外键、活跃单唯一索引、冻结与不可变/状态/一致性触发器；无旧数量回填或旧流水修改。已部署的历史迁移没有改写。

旧API的公开可售查询不认识盘点冻结，因此迁移与应用必须一起切换，不能混跑。旧写代码遇冻结会被数据库拒绝，不能将其错误视为安全兼容运行。回退只可使用支持当前冻结、快照和两级流水协议的兼容代码，保留表和历史事实；禁止reset、删流水或用SQL改数来“回退”。实际数据修复需单独审查和有凭证的业务动作。
