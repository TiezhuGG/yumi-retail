# 运营积分商城补齐与完成度核查（2026-11-06）

负责人要求核查运营积分商城、商品可填写价格和积分、查看所有顾客资料并进行积分操作；明确确认售价与兑换积分分别设置，兑换只扣积分。本轮交付范围为联合商品创建及顾客中心，保留已有积分审批规则。功能全貌、未完成项与建议见[运营商城核查](../product/ADMIN-MALL-V1.md)，不能标记商城整体完成或上线。

## 实际完成

- 商品管理“新增商品”和兑换商品“创建全新商品”共用表单，填写现金售价和可选兑换积分、分类/规格/单位/编码、效期、说明和原因。元转整数分，积分为1至10亿的整数字符串，省略可选说明可保存；禁止非法小数积分和金额。默认建立真实商品/SKU与本仓兑换草稿，不生成库存或启用支付。
- 新POST /admin/mall-products将商品、SKU、可选兑换商品、审计及幂等结果一次提交。重复原键不产生两条记录，改内容409；晚兑换审计失败整笔回滚，原键可恢复。基础商品插入复用原服务逻辑，旧创建/编辑/上下架接口保留。
- 后台兑换列表并列显示售价与兑换积分，匿名消费者积分商品接口保持原契约，不引入同时付款扣分。现有商品现金改价仍在商品管理，积分价格仍在兑换商品中维护；联合入口先创建一个SKU，其他规格沿用原入口。
- 新“顾客管理”读取全部现有顾客账号，包含零余额/停用账号，名称、微信/开发来源、正常/停用筛选和20条游标分页；详情展示已采集基础资料、最近登录、余额、本仓两类订单数量和待审数量。不返回微信原始身份、哈希、token、地址或密文；账号尚未采集绑定手机号/头像，收件资料继续在订单履约页面使用。
- 顾客详情直接查看积分明细、发放和误发冲正。发放对象固定为当前顾客，申请队列与冲正来源由API按userId和原经营仓过滤；仍使用原申请/独立审批、预算、来源额度、余额、防重及不可变账本机制，不提供无依据扣分或直接修改余额。
- 未确认写入结果时保留原请求并禁用编辑/退出，使用原键恢复；资料切换时避免显示旧顾客操作，失去权限清空已读个人资料。手机布局简化重复提示，资料分组为卡片，积分说明列不复用窄操作列。
- 新接口均校验权限、当前会话/角色及经营仓；写入含Origin/CSRF及UUID操作键。联合创建前后复核资格，顾客资料RepeatableRead读前后复核，不能仅靠隐藏按钮授权。
