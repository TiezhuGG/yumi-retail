# 库位、批次与库存核对交付

日期2026-10-27，本机Windows/Docker Desktop/PostgreSQL17.11。范围在实现前写入[切片边界](../roadmap/LOCATIONS-RECONCILIATION-SLICE.md)。没有新增/升级依赖，没有接入真实支付。

## 实际交付

- 新增warehouse_locations、stock_positions、position_ledger、stock_transfers、inventory_checks；库存增加核对销售暂停标识，业务审计增加可空原因。202610270003_locations_reconciliation及004_require_position_entries在本机开发/测试库部署。
- 旧数据先验证汇总/批次/主流水一致，事务迁移回填真实位置和位置历史流水，原主流水不改；异常输入拒迁移。StockLot数量保留为批次缓存，位置为真实分布，lot.location_code仅历史兼容字段。
- 库位创建/空位启停、默认位保护、无成本的批次位置/位置流水、同仓显式移位。一次移位产生主流水零增量及位置−N/+N，数量/业务单/审计/幂等结果同事务，源预占时拒绝移动，过期移位不恢复可售。
- 按SKU核对汇总、批次、位置、两级流水，逐位置检查防差额抵消。差异设置inventory_hold，公开可售0、收货/移位拒绝；报告不修数。重新核对一致仍保持暂停，独立解除动作需原因/余额版本并再次核对。
- 后台/移动作业端接入库位、移位、分页位置流水、单SKU核对及报告/解除暂停。写权限仅管理员/仓管；拣货员只读无成本数据，骑手不得访问仓储。前端切换规格时丢弃旧查询结果，避免旧报告/余额覆盖新选择。

## 浏览器实际验收

正常流程：登录→创建A-01“一号货架”→10件从DEFAULT移3件→位置7+3、仓库10、公开available=10→位置流水显示+3→核对报告“账本一致”→停用有库存的A-01被拒绝；移动作业端读取相同分布与报告。

异常流程：仅在一次性测试schema注入汇总11/位置合计10差异→浏览器执行核对，报告差异且账面仍11，公开可售0→仅在测试schema排除注入故障恢复10→执行一致核对仍显示核对暂停→填写原因并提交明确解除→公开可售恢复10。此测试SQL不是生产纠错方案，不交付数量改写接口。

此次浏览器检查覆盖核心操作与异常分支，尚未完成移动真机、完整弱网/多页切换E2E、微信工具和小程序真机。开发时共享包构建可能触发Vite整页刷新；验证待页面稳定后执行，不把开发热更新当成正式交互。

## 迁移与本机演示

保留现有.env与数据卷。先停止本项目旧API/Worker，再按顺序执行：

```powershell
npm.cmd run db:up
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run db:migrate:test
npm.cmd run build
```

如尚无本地样例，先按README完成setup:local/db:init/db:seed，再运行db:seed:catalog。重复seed不把已移动的库存移回默认位，也不重新加库存。分别启动dev:api、dev:admin、dev:ops；账号在本机忽略的.env中，勿粘贴到聊天/日志/提交。

在收货工作台下方“库位、批次与账本核对”：新建普通库位，选择源批次位置、目标库位、整数件数与原因，确认移位；查看位置流水，选择规格执行核对。位置/库位/报告有游标加载更多，可按规格UUID筛选位置。核对差异暂停后不允许继续入库/移位；实物/账务调查与纠错流程待后续模块，不能直接改数据库数字再当作业务完成。

复现检查：build后依次运行lint、format:check、typecheck、test:s0、test:s1、test:s2、test:inventory、verify:mini（均为npm.cmd run命令）。Prisma模型比对只能证明可表达结构一致，CHECK/触发器另由集成测试验证。

## 兼容性、限制与接续

迁移保留旧列、旧主流水和数量，不清库；但写协议已升级，旧收货代码缺少位置账本时会提交失败，禁止旧新写服务混跑。回退应用必须保留新位置账本写协议，不能简单运行S2旧写代码或删除历史表。若前置核对失败，保留现状调查并按受审查的纠错方案处理；不要跳过检查、修改已应用迁移或执行reset。

库位目前都是普通存储位，没有不可售区转换；收货先DEFAULT再移位。批次数量仍为缓存，需要与位置/账本同事务维护。核对是单SKU人工动作，报告前100项并保留全量差异数，没有全仓定时扫描/外部告警，尚未核对未来订单预占归属。差异修复、盘点冻结/审批、报损、逆向纠错和后台任务仍待开发。
