# S6 拣货资格与预占只读核验 · 2026-11-01

本轮交付S6首个前置切片：负责人、仓管、拣货员在授权仓库查询订单备货清单，核验原分配的批次库位预占及阻挡原因；后台与实际移动作业端均可运行。没有领取、实拣、缺货决议、出库或骑手任务，不声称S6整体完成。

## 范围与业务边界

现有正式订单数据库只允许待付款/取消，真实支付未接入，不能安全创建可领取任务。本轮保留原状态约束与预占不变量，合成成功证据/支付准备单不能把订单变为已付或可拣。

新增picking.read只读权限分配SUPER_ADMIN/WAREHOUSE_MANAGER/PICKER，运营/骑手不能读；拣货员仍不能访问后台order.read。API按当前授权仓库重新校验，不暴露顾客、地址、私密备注、金额、请求/幂等键和密文。无迁移或演示业务数据写入。

列表按订单号前缀和游标每页20笔，包含待付款/已取消，不冒充待领取队列。详情使用真实商品快照和订单分配，展示需求、未释放数量、批次/效期/库位及原因。所有详情claimEnabled=false，始终包含READ_ONLY_PHASE；另列订单取消/未激活、付款未确认、履约未就绪，以及预占释放/不匹配、冻结、库位停用、批次到期。

详情在同一RepeatableRead事务读取订单/分配/库存，核对本单同SKU及批次未释放量与当前预占承载量；取消并发读取不能混入另一次快照。它是只读诊断，不锁库存、不领取、不扣实物、不作为以后作业凭证。未来写动作仍需重新实现事务内资格/权限/范围/归属、领取竞争、逐行核对、异常决议及幂等出库保护。

## API与兼容性

OpenAPI0.27.0，已由实际应用导出：GET `/api/v1/warehouse/picking-readiness` 与 `/:id`，只接受规定仓库/搜索/游标参数。严格400、匿名401、角色/仓库范围或启用403、本仓订单/游标不存在404。未开放claim/complete/ship，POST均404。旧订单、消费者、库存及支付契约兼容。

没有数据库模型变化或迁移；角色权限在代码中扩展只读项，不新增真实员工或经营种子。经营规则、订单提交、真实支付及自动查询配置均未修改。
