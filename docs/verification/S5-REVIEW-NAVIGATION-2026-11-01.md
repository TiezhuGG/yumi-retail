# S5 核查跨页入口与返回定位 · 2026-11-01

本轮完成通知/支付尝试详情进入核查时间线、精确证据定位与返回来源。沿用现有UI与实际API，无后端规则、接口、数据库迁移或经营配置变化。

## 范围与验收案例

- 已关联通知携带实际仓库、尝试及该通知引用；独立通知没有关联入口。支付尝试携带最后一条已读尝试事件引用。目标重新读取API，不把来源旧状态当成最新事实。
- 已知成功记录可以不在异常列表，仍能查看关联详情；不可核查的记录不能保存备注。其他筛选条件保留。
- 返回来源保留当前仓库、已加载分页、详情选择、候选绑定及操作上下文，恢复原按钮焦点和滚动；返回提示说明内容是已读快照，刷新获取新事实。
- 三个页面仅首次访问后保留在当前工作空间；核查草稿及未确认保存的原请求键/文本/版本按仓库+尝试保存在内存。切换仓库和目标可恢复，刷新页面/退出或账号、会话、角色、权限范围变化时清空；不写入localStorage/sessionStorage或URL。
- 目标失败不残留旧详情，可重试或返回。隐藏页迟到响应不抢焦点。目标即使来自缓存来源，仍由服务端重新鉴权，撤销仓库后403拒绝读取。
