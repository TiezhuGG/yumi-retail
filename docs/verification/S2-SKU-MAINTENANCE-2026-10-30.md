# SKU售价与启停交付

日期：2026-10-30。接续上一提交9116d7d的商品基本资料编辑，按负责人授权自主沿用现有UI风格。本轮边界是单个SKU的售价、启用和停用，不包括改编码/规格/单位/效期规则、分类维护、条码、交易或支付。

## 实际完成

后台 http://127.0.0.1:5173/ → 商品管理 → 每个规格行“售价与启停”。独立窗口先读取当前Product/SKU；规格/单位/编码只读，售价填写元并精确转换整数分（0.29→29），范围0.01–1000000.00元、最多两位小数。未保存价格时禁用启停，避免误丢输入。只读角色无维护入口，服务端继续鉴权。

停用规格从消费者公开列表/详情隐藏，阻止新建收货及未过账单入库；原库存、批次、库位、收货成本与流水保留。启用不自动上架商品。已上架最后一个启用规格须先显式下架商品再停用；草稿/已下架可全部停用，全部停用不能上架。此为本次实现保护规则，未宣称正式业务/上线验收已确认。

价格、启停、商品基本资料和上下架共用Product.version与Product行锁；SKU写锁与收货新建/过账共享锁串行，避免启用校验和停用竞争。成功推进商品版本；旧版本409，重复状态409，最后启用规格409。审计SKU_SET_PRICE / SKU_ENABLE / SKU_DISABLE记录SKU、员工、商品、版本及旧→新售价/状态，与幂等结果同事务提交；晚期错误全部回滚。无需DDL/迁移、新权限或新依赖，返回原Product/SKU结构。API、PRD、数据设计、UI说明及实际OpenAPI已同步。

响应未知时冻结内容/动作并保留原幂等键重试；冲突保留当前输入并明确提供替换载入。确认操作后关闭窗口并GET刷新列表，不将历史幂等响应当作当前价格。已确认但刷新失败明确提示刷新核对。关闭窗口后没有持久化保存未知提交意图，可重新读取当前资料核对，不能声称具备跨设备意图恢复。
