# S5 合成通知记录与持久化去重 · 2026-11-01

本轮交付独立合成通知记录表、真实验签后持久化/去重和后台“通知记录”页面。不接收真实微信回调，不入账、不修改订单/支付准备/库存；真实渠道保持disabled。上一轮提交8aafc1b已完成密码学基础，本轮在此基础接续。

## 边界与行为

- 管理员在显式开启的本机环境创建合成通知；操作键由界面生成，不要求用户输入内部UUID。服务端临时生成RSA/AES材料，真实调用原文验签、解密及绑定核验核心后才持久化。
- 独立表保存最小事实及摘要；无报文、付款人、完整明文或密钥字段。标识强制合成前缀，与真实订单/支付准备没有外键关系，页面状态始终“仅记录、未入账”。
- 同仓同通知ID以事务锁和唯一约束保护。固定字段顺序的已验证事实摘要一致时返回原记录；相同ID的事实改变返回409，原记录不可覆盖。签名、密文和接收时间不参与事实摘要，因此重新加密/签名仍能去重。
- 首次记录及NOTIFICATION_LAB_RECORDED业务审计同事务提交；审计失败不留孤立记录。重复重放不增加记录或审计。本轮不持久化重复尝试次数/冲突记录，不提供处理队列或完成状态。
- 重启后的新应用实例依赖PostgreSQL读取原记录，不依赖临时密钥或进程内缓存。
- 仓库授权、仓库启用、管理员权限、Origin/CSRF和严格输入在服务端校验。复用payment-readiness.read（默认仅SUPER_ADMIN）。开关PAYMENT_NOTIFICATION_LAB_ENABLED仍默认0，生产/公开绑定/非本机开发测试库拒启；只读查询可用，默认POST503。

## API 与兼容性

新增/api/v1/admin/payment-notification-records的GET列表、GET/:id详情、POST创建及POST/:id/replay重放。创建仅接收{key:UUID}，重放仅{}，不接受真实报文或密钥。列表20条，以createdAt/id稳定降序游标分页，详情和游标限定当前仓库。未知输入400、未登录401、无权限403、记录/游标不存在404、事实冲突409、默认关闭503。

API版本0.17.0，实际OpenAPI已导出；支付接入检查仍明确BLOCKED。新增迁移202611010003_notification_lab_records，仅增独立表/唯一约束/索引/不可变触发器，无既有业务行变更。数据库拒绝修改和删除合成事实。依赖和锁定版本未变；本机Node24.22.0与声明24.22.1的既有差异保持，并未声称重新验证Windows版本。

本机Docker Desktop未运行，继续使用Docker Engine29.9.1及既有PostgreSQL17.11环境。核实本项目旧API/Worker/后台进程后停写，两库迁移成功，恢复新版服务。其他环境需停旧写入、迁移、生成客户端/构建再启动；可保留新表退回旧应用，不能靠删除事实或清库回退。
