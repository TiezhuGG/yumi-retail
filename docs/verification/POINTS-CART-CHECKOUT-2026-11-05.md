# 积分购物车与实际兑换交付记录（2026-11-05）

## 本轮边界与验收

用户要求优先完成积分兑换、加入购物车、一次兑换多个商品；“兑换订单”改“订单”；普通页面用左上角返回；现金下单支付留作后续接入。本轮完成本地开发功能与浏览器验收，未发布生产。购物车最多20种积分商品，只保存在本机，按API环境/账号隔离；未登录草稿通过明确按钮导入，不承诺跨设备同步。

验收场景：两种SKU按不同数量统一报价/确认，准确扣除总积分并预占全部库存；同键并发/网络响应丢失恢复不重复下单；总积分不足/过期/中途数据库异常整次回滚；一笔完成后可继续立即兑换，直接兑换不误删购物车；账号切换不显示另一账号草稿。

## 实际实现

- 原生四导航：商城、购物车、订单、我的；登录、商品错误态和范围页的重复返回按钮移除，普通页面沿用微信原生返回，首页等导航页不制造返回栈。
- 商品详情可加入购物车或立即兑换。购物车支持数量调整、删除、勾选/全选、按现价估算积分、缺货提示和结算。加入时不预占；API不可用商品禁止结算，可删除后重新选择。
- 新 `/consumer/redemption-cart-quotes` / `/consumer/redemption-cart-orders` 使用同一PostgreSQL事务，报价及提交均核验本人会话、开发/受控/正式门禁、同一地址/政策、各商品版本/配额/库存及总积分。统一锁序和末尾效期检查；未知失败使用原键恢复。
- 一次确认按商品生成独立订单（不是合并包裹）；各自继续复用原打印、人工快递发货、取消退款和按件售后。本轮无迁移，58项原迁移及数据库强约束保持，OpenAPI更新0.61.0。
- 本机原请求持久化包括账号、报价数组、原键和结果。成功后仅清理对应购物车件数，消费标记和数量一次存储写入；直接兑换不清理购物车。完成后的下一次兑换可建立新请求；处理中切到后台再回来不会永久卡在忙碌态。
