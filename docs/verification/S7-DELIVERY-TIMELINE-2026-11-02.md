# 合成配送凭据时间线与异常追溯 · 2026-11-02

本轮只读聚合已有合成出库、分配、接货、开始、异常上报、异常处置、合成送达事实，增加详情时间线、异常相关过滤及定位焦点。无迁移、无新增状态迁移或写入动作，无顾客/订单/库存/支付关联。

任务DTO新增timeline数组，最多7个节点，每项{id,kind,createdAt,actorName,reason,relatedId}。id为来源类型+凭据ID，kind限定DISPATCH/ASSIGN/HANDOFF/START/EXCEPTION/RESOLVE/COMPLETE；relatedId关联上游分配/出库或原异常，RESOLVE明确指向原异常ID。仅出现已保存事实，不补造未来节点。姓名取出库/分配/处置的不可变快照，骑手动作取原分配骑手姓名快照；不读取当前姓名冒充历史身份，不暴露原请求键或员工内部编号。

按凭据createdAt升序，同毫秒按固定阶段顺序、再按来源ID排序；这是记录时间和确定性展示顺序，不代表另行确认的实物发生时间。列表、详情与动作恢复返回的时间线均复用现有授权及同一任务事实读取；负责人/仓管只读本仓，骑手仅本人，当前停用/撤权继续受原服务端鉴权限制。历史事实不因当前资格变化被改写。OpenAPI0.37.0从实际应用导出，新增字段为兼容扩展。

UI在详情中展示时间/操作者/异常类型，支持全部凭据或仅异常上报+处置；无异常时显示明确空态。定位按钮将相应凭据区域滚入视野并赋予键盘焦点，异常处置定位到保留原异常及处置凭据的同一详情区。内部编号不作为普通输入；所有记录明确标注隔离合成。当前资格独立展示，不从历史时间线推断可操作权限。

实际验证：配送23项真实PostgreSQL用例通过（原22+新增1）；新增覆盖未分配只有出库节点、完整7节点、来源ID去重、原异常关联、请求键/骑手内部ID不泄露、账号改名/停用后历史姓名保持、当前骑手失效及他人详情拒绝。原状态竞争、幂等、异常阻断/恢复、审计回滚、列表概览分页和真实库存订单不变回归均通过。

API/Worker/共享包构建、全工作区typecheck、后台/H5构建、lint、修改代码Prettier和diff检查通过。沿用Node24.22.1原生类型转换、Vite runner，锁文件和依赖不变。本轮未重跑小程序编译、微信工具/真实网络或真机，原用户目录权限限制未解决。
