# 异常清单到时间线定位与返回恢复 · 2026-11-02

本轮只调整共享Web交互，无API契约/数据结构/权限/状态动作变化，OpenAPI仍0.37.0，无迁移。异常卡片新增“追溯当前异常凭据”：未决异常直达EXCEPTION节点，已有处置直达RESOLVE节点，自动切换异常相关时间线并滚动/聚焦具体事实。使用本次详情API返回的凭据，不用旧卡片推定已处置或替代当前鉴权。

返回保存本组件内当前仓库/筛选、已加载页数、来源按钮及滚动位置。按当前筛选从第一页顺序重读原页数，使用新响应游标，不复用失效游标；成功后展示新列表并恢复来源按钮焦点。若来源任务已不在本次加载结果中，提示该情况并聚焦列表标题，保留筛选，不声称任务不存在或已完成。多页是逐请求读取，不承诺跨页固定数据库快照。

返回读取失败保留详情及原页数/筛选，重试重新读取整段列表，不展示部分成功页；401/403清除列表和详情缓存。操作仍按原授权API执行，未知动作请求继续原键恢复；不因导航丢失本浏览器进程内原请求记录。本轮不实现URL分享、跨侧栏/整页刷新后的导航持久化，不新增普通UUID输入。

实际验证：共享UI编译、全工作区typecheck、后台/H5构建、lint、代码格式和diff检查通过。实际API+PostgreSQL临时schema浏览器验证直达上报/处置节点、DOM焦点、返回筛选/来源焦点、OPEN任务处置后结果变化、21条20+1页面恢复、返回503保留详情及原两页重试、角色隔离及原请求恢复回归。36张本地截图，390手机和1440桌面无横向溢出；人工查看手机直达异常布局。

验证脚本修复了两类等待问题：等待列表分页渲染和React焦点effect；对“提交成功后丢失响应”注入，等待原请求重试按钮可用后再刷新，防止在原POST仍提交时读取。早期脚本的定位/计数及请求交错失败不计为通过；修正后完整脚本通过。本轮未重跑历史23项PG套件，服务端/数据库规则未改，PG验证来自真实浏览器夹具及其事务。
