# 商品上架检查（2026-11-06）

本轮边界：补齐运营积分商城清单中“集中检查上架条件与维护入口”，复用已有发布/库存/权限规则。成功标准为真实数据可追溯、提醒不冒充阻断、源商品和积分商品明确区分、检查后变化仍由实际写动作裁决。无新经营门槛或生产验收结论。

## 实际完成

- 新增GET /admin/rewards/:id/readiness与共享契约，员工points.write及当前经营仓授权；RepeatableRead内读前后复验会话、角色和仓权限。返回当前商品/规格/规则快照及10项检查，不写商品、库存、积分或发布凭据。
- 兑换商品“查看商品”中展示上架前检查：分类、基础商品、规格、售价/兑换积分、封面、开放时间、库存、快递范围/运费、提交开关和积分商品状态；区分READY/WARNING/BLOCKING/INFO。
- 停用分类/父分类、未上架源商品、停用SKU、开放时间已结束按原写约束标阻断。缺封面、缺货、未来开始时间、快递或兑换提交尚未配置标提醒，不新增“必须有图/有货才可上架”的经营规则。已上架状态不再宣称可执行首次发布；公开展示条件与可兑换/正式上线分开。
- 库存独立于草稿/上下架计算，采用现有余额减预占/隔离/安全量、有效批次/启用库位的较小值，冻结/盘点为0；不会将“草稿有实物”误报为无库存。实际展示可用量再叠加源商品/分类/SKU可见条件，实际提交仍需预占。
- 连接原分类、商品资料、图片、SKU售价/启停维护；管理员可前往库存，运营无库存权限时明确由仓库维护；可前往快递配置及首发检查。分类停用时传递准确的父/子分类定位，不依赖文案解析。
- 基础商品上架提供独立确认，说明影响其全部规格、积分商品仍须单独发布；使用原权限/版本/幂等接口，响应未知保留原键，防止重复写。刷新报告更新详情和后续编辑版本；加载/错误期间隐藏过期检查项，错误可重试。
- 封面仅检查有效元数据，不冒充文件加载或图片内容验收；快递仅反映规则配置，不认证承运条件。报告不返回成本、图片对象键、顾客资料或密钥，canPublish不作为授权令牌或库存预占。
