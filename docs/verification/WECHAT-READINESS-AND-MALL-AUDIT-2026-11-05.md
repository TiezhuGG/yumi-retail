# 微信登录接续与积分商城未完成项（2026-11-05）

负责人最新确认：小程序和服务器均未准备。本轮不注册账号、不购买资源、不填写模拟凭据冒充真实账号、不启用真实微信或生产交易。此前页面精简和普通构建关闭开发入口的未提交修改继续保留。

## 本轮实际完成

现有真实登录链路已在源码实现：小程序Taro.login取新code → `/consumer/auth/wechat-session` → 服务端固定HTTPS微信code2Session → OpenID哈希绑定本系统WECHAT身份 → 随机会话token/数据库哈希 → 恢复/退出/鉴权。新微信账户不自动赠分、不迁移开发身份，不读取微信昵称、头像或手机号。原实现不需要再伪造另一套登录。

本轮补齐：

- 真机构建检查两处源工程AppID相同且为真实格式，拒绝游客/占位AppID；指定 `TARO_APP_WECHAT_APP_ID` 时必须匹配。输出工程也必须匹配才生成清单。公开AppID写入构建清单，真机验收复核三个导入工程；旧清单需重编译，数据库无迁移。
- `pnpm check:wechat:login` 提供脱敏只读检查：登录配置、AppID/服务端密钥、工程匹配、HTTPS API、有效真机构建和开发开关。它不联网、不读数据库，不输出凭据、账号ID或URL值；静态准备通过也不代表已真实登录或可以上线。
- 登录失败后主按钮可直接“重新微信登录”，每次调用重新获取code；保留读取本机异常会话时的检查入口。当前普通构建没有开发顾客A/B按钮。
- 更新当前登录页/我的页的同源码浏览器验证，覆盖加载/方式失败/暂停、取code失败、失效、响应丢失后新code重试、同账号只建一个用户、零余额、恢复、退出及隐藏取消。截图明确标注合成微信适配器。
- 首发检查商品文案去掉已取消的配额条件，保留最新不限额规则。

## 实际本地状态

只读汇总：59项已应用迁移、21个上架积分商品、7个消费者可见分类（数据库8个启用分类，不等于8个都公开）；全部现有用户只有2个DEVELOPMENT身份，真实WECHAT用户为0。只有2条已取消的开发兑换订单，售后申请0。2个演示积分账户；积分发放政策关闭；快递政策是1个省份/商家承担运费的本地演示配置。

服务端没有真实WECHAT_APP_ID/AppSecret，微信登录未启用；消费者工程/产物仍是touristappid，根工程另有一项未确认归属的AppID，二者不一致，本轮保留原文件而不冒认已有可用小程序；当前API为本机HTTP，构建为local。现阶段 `check:wechat:login` 正确报告 `configurationReady=false`、`realWechatVerified=false`、`networkChecked=false`、`canLaunch=false`。该结果是环境缺失，不是把现有代码当作真实微信已经联通。
