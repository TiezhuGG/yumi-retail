# S5 后台订单查询与预占明细 · 2026-11-01

接续上一轮订单预占，交付授权仓库内的订单列表、服务端筛选、分页和独立详情；沿用当前后台UI。此轮是只读查询，没有新增支付、履约或代客改状态能力，经营规则与开发下单开关不变。

## 范围与验收案例

- SUPER_ADMIN/OPERATIONS通过新增order.read及原有显式仓库范围查询。匿名/消费者不可访问；仓管/骑手无默认权限；无范围、仓库停用拒绝；其他仓库订单和无效游标不返回资料。
- 仓库、状态、订单号前缀筛选由服务端执行，20笔一页，游标匹配同仓库和同筛选。使用真实结算/下单/取消接口创建22笔合成订单，分页没有重复或遗漏。
- 详情金额/商品来自不可变订单快照，批次/库位与预占/释放时间来自原分配和两级流水；不把仓库汇总库存当作本单数量。
- 联系密文和消费者身份不进入查询选择，API/UI不返回联系人、电话、门牌、地址/订单备注、幂等键/摘要、原报价ID、请求编号或事件payload。
- RepeatableRead确保并发取消时状态、释放和事件为同一快照；读取前后库存数量/版本、流水和事件不变。
- 桌面/手机、空/加载/错误、详情刷新/失败、更多失败重试、刷新失败重试及晚到响应保护均实际验证。

## 实现与兼容性

新增GET /api/v1/admin/orders和GET /api/v1/admin/orders/:id，必填warehouseId；列表可选status/q/cursor。严格额外字段、数组/重复参数、ID、状态及订单号前缀校验。订单按createdAt/id倒序，游标锚点必须匹配筛选；不存在/跨条件游标404，范围/停用403，身份401。

后台侧栏新增“订单查询”，与商品/报价规则保持一致；列表与详情分离，按名称选仓，不输入UUID。手机端后台使用单列布局；此次不为移动作业端仓库角色增加订单入口。详情不解密顾客地址，库位名称取当前主数据且界面已说明。无总销量、虚构支付结果或无响应入口。

无数据库迁移、依赖/版本变更，原订单取消/超时/预占和不可变约束未改。权限在每次请求重新读取，现有员工无需数据回填；新增权限仅授予运营/超级管理员，不放宽仓库范围。订单查询不会派发履约或消费Outbox事件。
