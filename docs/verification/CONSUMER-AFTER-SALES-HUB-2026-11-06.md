# 消费者售后入口补全（2026-11-06）

## 本轮范围

将已有的退货退积分申请和售后反馈都从“我的→售后服务”提供独立查询入口。两种业务继续使用自己的状态和原处理流程。

## 实现内容

- 退货退积分列表顶部新增“售后反馈”入口；反馈页可按全部、待门店处理、处理中、已结束筛选，按商品名/订单号搜索、游标分页、下拉刷新和错误重试。
- 每条反馈摘要显示商品、问题类型、订单号、最近更新时间；选择后进入原兑换订单详情，继续使用已有反馈历史、补充和重新反馈能力。
- 新增 GET /consumer/redemption-after-sales，只读取本人 EXPRESS 订单及其反馈记录；过滤条件与游标同查询限定本人记录。响应不含反馈正文、地址或员工身份，no-store。
- 无数据库迁移，无新的反馈写入、审批、积分或库存动作。

## 本地收尾与验证

- 共享契约和 API 编译、小程序 TypeScript 检查、小程序编译、相关文件 ESLint 均通过。
- OpenAPI 已从实现导出为 0.68.0。
- 收尾补齐2项真实PostgreSQL列表专项与7项原售后反馈回归，分别运行通过：三种状态、20+3分页及状态与关键词交集、特殊字符字面搜索、本人/他人/未登录、游标归属与状态变化失效、摘要字段白名单、no-store及读取不增加库存/积分/反馈事件。
- 分页样例以真实收货→报价→兑换→快递发货→反馈动作建立23条记录，仅写临时测试schema并在结束清理。首次规模样例触发20次/120秒报价保护，后改为等待报价自然到期；没有禁用限流、不可变凭据或数据库约束。
- 同源码React、真实API与临时PG浏览器验证：手机390及桌面1440的完整流程通过，共19张截图；另以3条样例复核失效登录及截图位置。覆盖访客、状态切换、分页、关键词搜索与清除、隐藏后恢复/下拉刷新、503错误重试、账号切换、跨账号详情拒绝；从列表进入原订单可读原文/门店回复、补充说明、对已结束记录重新反馈。浏览器无运行异常或横向溢出。
- 修复反馈列表401后残留原状态筛选：现在同时清空列表、游标、搜索与状态选择，展示登录入口；浏览器注入401复验通过。
- 反馈页去掉重复页内标题及额外返回按钮，返回使用微信左上角。三个原生tab页（购物车、订单、我的）移除重复标题的已有改动，通过当前编译包React运行数据检查和同源码页面截图复核；此证据不等于开发者工具中已加载相同产物。
- 新增页面已登记到小程序入口配置。全项目类型检查、相关文件ESLint、完整本地weapp构建、全部页面及三个导入工程产物检查、四个原生tab和登录页编译运行检查均通过，已更新本机构建清单；开发顾客入口保持关闭。

本次收尾未改变既有API行为或数据结构，OpenAPI仍0.68.0，迁移仍61项；无需改业务主库、经营参数或交易门禁。日志位于本机 .local/feedback-{build,tests,list-tests,ui-full,ui-small,typecheck,lint,mini}.log；截图使用合成数据，本地忽略，不提交凭据及运行日志。
