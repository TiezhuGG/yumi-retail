# S7 合成骑手任务分配与交接资格基础 · 2026-11-02

本轮完成已合成出库任务的负责人/仓管分配、本仓启用骑手选择、骑手本人任务列表/详情、动态交接资格核验和原请求恢复。页面连接实际API，延续绿白卡片和角色导航；没有接货、送达或真实配送写入。

## 边界与验收

- 任务来源仅为原picking_lab_dispatches。负责人/仓管可查看授权仓库内全部合成出库，按姓名选择启用、具备RIDER且有本仓范围的员工。
- 每份合成出库最多一份不可变分配事实。不提供改派、撤销、覆盖或自动调度。原人员/键/骑手重试恢复已成功结果，改骑手、换键或换人拒绝。
- 骑手只能读取本人已分配任务，列表、详情和游标均附加本人条件；未分配/他人详情统一404，不开放候选名单和分配写入。
- 交接资格核验对象为被指派骑手，取当前账号/角色/仓库范围和原拣货出库快照。停用/撤权显示明确阻断，历史凭据仍保留；ready不等于当前查看者有接货操作权。
- 不使用真实顾客、地址、订单、库存或支付关联。不执行接货/送达，沿用PICKING_LAB_ENABLED默认关闭、生产拒启。真实交易仍受原经营/支付/真机门禁约束。

## 模型、契约与兼容

202611020001_delivery_assignments已应用本机yumi_dev/yumi_test；新增不可变delivery_lab_assignments，dispatch_id唯一，FK合成出库/骑手/分配者，保留姓名/键/时间快照及骑手索引。仓库从dispatch→pack→task推导，不设重复可漂移字段；旧任务不补造分配事实。Prisma Client已生成，索引映射与SQL名称一致。

插入前锁对应原任务，数据库和应用均校验启用骑手/RIDER/本仓权限，资格行共享锁与撤权/停用提交串行化。不可变触发器拒绝UPDATE/DELETE；审计和分配事实同事务。读取列表/详情使用RepeatableRead快照，资格撤销不篡改历史。

OpenAPI0.31.0从实际应用导出，新增delivery-lab的warehouses、riders、分页列表、详情及assign接口。管理员/仓管有read+assign，RIDER仅read；没有额外授予骑手warehouse.read。新DTO为包裹数/出库时间/可空分配凭据/资格阻断；不暴露原键和人员内部编号。PRD、API、数据、UI及路线已同步。

先迁移再部署新服务；原拣货/打包/出库/正式订单状态不变。回退须关闭演练写入并保留凭据，不提供删除事实脚本，不允许忽略分配事实的旧服务继续交接。
