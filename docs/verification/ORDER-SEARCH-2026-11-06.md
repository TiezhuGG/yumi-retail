# 消费者订单搜索（2026-11-06）

范围：本人积分订单按商品标题/订单号搜索，与现有状态筛选、分页、刷新和售后入口组合。验收案例是从多页订单找出指定订单、切换状态、清除搜索、刷新/返回、换号和处理迟到响应。不是现金支付或新的交易状态动作。

## 实际完成

- 订单和售后列表新增“商品名或订单号”搜索框、搜索/清除操作；支持部分、不区分大小写匹配，首尾空白清理，最多80字符。
- 仅本人资源，搜索与状态取交集；百分号、下划线和反斜线按字面匹配。没有匹配时显示“没有找到相关订单”，可清除搜索，区别于没有任何订单。
- 已提交条件与输入草稿分开：触底加载、下拉刷新及错误重试保留已提交关键词；新的搜索/状态从第一页开始，旧请求晚到不会覆盖新结果。
- 同账号从详情返回恢复已提交条件；从“我的”明确进入指定状态或查看全部时清空旧关键词，查看全部恢复全部状态。页面隐藏先清除可见搜索词，身份确认后才恢复；换号/退出清除原账号关键词与结果。
- 搜索框保持44px触控高度，普通页面没有增加介绍文案或刷新订单按钮。

## API、数据及兼容

OpenAPI 0.66.0，GET /consumer/redemptions追加可选keyword，返回结构/no-store/身份校验保持，游标同时校验本人、关键词及状态归属。旧客户端省略关键词行为不变，员工已有搜索规则保持。

无数据库模型、索引、迁移或历史数据变更，仍61项迁移；无搜索词持久化和搜索历史表，访问日志只记录路由模板。读取不会扣分、预占、修改订单或收货/售后事实。API已核验本项目进程后更新运行，小程序普通本地构建已重新生成，开发顾客入口仍关闭。
