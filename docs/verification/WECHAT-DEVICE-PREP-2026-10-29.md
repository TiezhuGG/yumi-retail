## 构建入口

- `npm run build:mini`：保留默认本地weapp构建，默认API不变；成功后额外验证工程入口/页面产物，生成忽略的 `.local/mini-build.json`。
- `npm run build:mini:device`：要求显式提供 `TARO_APP_API_BASE_URL`；本项目真机准备策略要求HTTPS和真实DNS名称、路径`/api/v1`，拒绝IP/回环/局域网名称/示例域名，以及含账号、查询参数、片段的地址。错误不回显传入的敏感字段。它不自动认证域名归属、微信后台合法域名、TLS或实际网络可达性。
- `npm run verify:mini:device`：要求清单target为device，核对API实际嵌入JS及所有输出文件路径/字节数/SHA256；缺失、增加或修改输出会拒绝沿用旧清单。清单不含AppID、账号或凭据，三个验收字段默认not-recorded，不生成虚假的验收通过状态。
- `npm run verify:mini`：原有三个工程根及首页/详情产物检查继续保留。

缺少/不合格API在启动Taro和删除旧清单前就停止，保留现有产物。实际开始编译后先移除旧清单，失败不再把旧清单当本次成功；本次产物仍使用原 `apps/consumer-mini/dist/`，本地和真机目标互相覆盖，不保留两套工程。原 `pnpm --filter @yumi/consumer-mini build` 仍可直接调用Taro，但不生成本轮清单；真机准备须使用根目录新入口。

`pnpm -r build`仍是既有全工作区构建，不生成真机构建清单。任何后续直接构建导致产物变化，真机清单核验会要求重新生成。

## 取得HTTPS测试API后

先确认负责人提供的公开API地址、当前AppID对应后台合法请求域名及测试数据范围；密钥和账号不放进URL或聊天。以下占位符必须替换，脚本会拒绝直接使用：

```sh
TARO_APP_API_BASE_URL='https://<已配置的测试域名>/api/v1' npm run build:mini:device
npm run verify:mini
npm run verify:mini:device
```

这里只设置该次进程变量，不会修改.env、微信工程或服务端配置。构建成功后核对 `.local/mini-build.json` 的target/API/时间/文件清单。**不要使用 `verify:mini:api` 测这个公网地址**：该既有脚本刻意只允许本机HTTP；真正域名网络/TLS/微信运行时请求另验，不能通过放宽旧本地检查冒充远端验收。

微信开发者工具导入根目录，使用现有负责人AppID并保持正常域名校验；点击编译，若与清单不符可仅清理本项目编译缓存再编译。先完成该HTTPS地址的工具运行时读取，再进行手机预览/调试；将源代码包发送至微信服务生成预览前另行确认具体AppID/目标版本，当前未执行上传。

手机的请求地址、系统、网络和实际页面要独立核对。默认loopback包不能作为手机联网包；ADB连接及模拟器截图不能代替微信真机操作。后续部署、域名购买/备案、账号连接或生产发布需另有明确授权，本轮只记录依赖。
