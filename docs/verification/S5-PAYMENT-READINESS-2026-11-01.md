# S5 支付渠道接入准备与配置校验 · 2026-11-01

本轮新增管理员支付接入检查页、只读API和离线配置命令。按非敏感字段格式、当前经营配置、尚未实现功能和待验收条件分开报告；始终channel=DISABLED、canStartPayment=false，没有连接商户、读取凭据或发起支付。

## 边界与验收案例

- 仅SUPER_ADMIN新增payment-readiness.read，并继续要求当前启用仓库的显式授权。运营/仓管/骑手/消费者不可读取部署元数据，停用/撤权即时拒绝。
- AppID/商户号/通知地址只做本地格式检查，不存或返回原值；未配置、格式不符、格式通过但未联通分别记录。通知地址不进行DNS/HTTP探测。
- 报价规则/服务范围从真实同仓库数据读取，已配置不等同经营验收；缺规则不写入样例数值。
- 渠道/通知处理未实现标BLOCKED，身份/绑定/凭据/HTTPS真机标UNVERIFIED；任何组合都不启用支付。
- 集中配置拒绝不支持的PAYMENT_MODE，包括mock；离线报告和错误不回显输入。
- 桌面/手机、规则暂停/缺失、加载/错误恢复、无仓库和角色隐藏均有实际验证。

## 实现

GET /api/v1/admin/payment-readiness?warehouseId=UUID，返回检查时间、仓库及11项状态。严格空/额外/重复/无效参数校验，Cookie鉴权与角色/仓库范围不依赖前端。报告事务RepeatableRead，不改变订单、库存、支付准备、流水或事件。没有POST、启用、凭据上传或保存配置接口。

新增可选非敏感环境字段WECHAT_PAY_APP_ID、WECHAT_PAY_MCH_ID、WECHAT_PAY_NOTIFY_URL，环境样例留空，实际.env未写入样例。应用配置阶段仅保存脱敏检查结果，修改后需重启。已有本机支付准备开关及真实支付disabled保持。

本地格式策略为AppID以wx加16位小写字母数字、商户号8–32位数字；通知地址限HTTPS域名/标准端口、非根路径及512字符，拒绝空白/控制字符/反斜线、IP/本地域名、账号、查询串和片段。此策略不代表微信官方已核验这些值或通知地址已可用。商户与AppID绑定、身份、签名验签材料均未接入，不能用格式通过替代实际验收。

`npm run check:payment-config`先构建后运行离线检查，仅输出前三项脱敏状态与禁止支付标志。缺可选字段退出0，INVALID或非disabled模式退出1；退出0不代表可以部署/支付。`npm run test:payment-config`运行纯逻辑测试，`npm run test:payment-readiness`运行真实数据库专项。

无数据库迁移、依赖/版本或业务状态机变更；API版本0.15.0。worker原支付禁用保护未改变，本轮不重启或修改超时任务逻辑。

## 本机交付

没有提交Git、上传小程序、生产发布、真实付款/退款或新增外部账号连接。下一项为支付通知验签与解密的隔离验证基础，真实渠道继续关闭，准备合成材料验证后再等待真实联调条件。
