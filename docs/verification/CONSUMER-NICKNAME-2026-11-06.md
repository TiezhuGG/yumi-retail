# 消费者昵称编辑（2026-11-06）

## 范围与验收

接续商城个人资料缺项，仅补齐本系统昵称编辑。入口位于“我的”当前名称右侧“修改昵称”，进入独立表单；没有重新增加页内大标题、账号设置空入口、头像上传、手机号绑定或微信资料读取。

验收案例：本人改名并在返回/再次登录后展示；空白/超长/隐藏字符拒绝；相同目标重试；两个设备保存不同昵称时不覆盖已变化的当前值；响应丢失后核实或原内容重试；换号清空原资料并隔离待核实内容；会话在写入中到期时整笔回滚。

## 实现

- 新增 POST /consumer/profile/nickname，消费者Bearer鉴权和no-store，严格只收displayName、expectedDisplayName。目标先去除首尾空白并NFC规范化，再限制1至20个Unicode码点；拒绝控制/格式/行分隔字符及完全由不可见组合字符组成的名称。原昵称以当前读取值原样提交，支持既有最长80码点显示名。
- 只使用会话user_id，不能传入其他顾客编号、provider或权限字段。事务按会话共享锁→本人用户行非键更新锁顺序，复核enabled、auth_version及真实到期时间；到期晚失败回滚。既有微信provider、subject、AppID、会话及积分不变；重新微信登录保持自定义昵称。
- 使用“当前值比对”处理并发：当前值等于原昵称时可保存；已经等于目标时也成功，供相同内容重试；同时不同于原值和目标时409/PROFILE_CHANGED。没有新增历史修订号，不冒称完整的历史版本检测或财务幂等凭据。
- 客户端在发送前按API环境和账号保存原内容；未知结果时冻结输入，可核实或重试。冲突后读取最新昵称、保留用户草稿，由用户再次确认保存；明确错误清理本次意图。不同账号不读取/提交原账号意图，界面隐藏/返回与存储会话变化均阻止旧响应回填。
- 输入框统一高度与居中，保存按钮、成功/错误、长度计数及加载/访客状态沿用当前风格。临时读取失败只提供重试，确认为未登录/失效时提供微信登录。
- GET /consumer/me补齐no-store；新增页面和产物清单，OpenAPI更新0.69.0。

- 17项真实PostgreSQL测试通过：4项昵称专项与13项消费者/微信会话回归。覆盖Unicode/20个普通emoji、重复保存、身份字段保护、严格参数、并发200/409、本人/他人/未登录、写入触发器延迟期间真实会话到期回滚、有效会话撤销与顾客停用、合成微信重新登录仍保留昵称且不赠分。所有写入在临时schema内，结束自动清理；没有请求真实微信。
- 同源码React、真实API与临时PG浏览器验收通过，手机390与桌面1440共15张截图。覆盖访客、初始表单、超长禁用、保存/返回我的、另一设备冲突且保留草稿、成功响应丢失后核实、请求未送达后原内容重试、账号待核实内容隔离、提交前换号阻断、读取错误重试及401清空资料。无页面运行错误或横向溢出。
- 实际查看最终“我的”编辑入口、昵称表单与冲突截图，修正浏览器默认输入框边框及入口多占一行问题。
- API/共享模块构建、全项目类型检查、相关文件ESLint、完整本地weapp构建、全部页面/三个工程入口检查及四个原生tab/登录页编译运行检查通过，已更新本机构建清单，开发顾客按钮保持关闭。
- 确认旧3000端口进程属于当前工作区及项目日志后平滑替换，保留实际.env配置。新版本地API健康live/ready均200，契约0.69.0包含昵称接口，匿名保存401。没有修改实际顾客昵称或经营数据。

## 兼容性与未验

复用consumer_users.display_name，既有数据不做自动变换，无新增模型/迁移，仍61项迁移。新增接口向后兼容；不调整授权身份版本、积分、订单、库存或经营参数。昵称是本系统自填资料，不同步修改微信账号昵称。

真实微信账号与HTTPS服务器仍待准备；小程序开发者工具/真机的输入法、键盘确认、页面返回与真实登录尚未验收。头像、手机号绑定、真实现金支付及商城生产验收未完成，不能据此称商城上线。
