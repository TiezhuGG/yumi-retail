# S5 支付准备单与幂等状态基础 · 2026-11-01

本轮接续后台订单查询，实现渠道调用前的本地支付准备单、幂等接口、取消/超时关闭联动，以及小程序/后台状态卡片。没有真实预支付单、微信支付调用、成功回调或退款；订单paymentState始终NOT_STARTED。开发准备复用本机订单开关，默认关闭，经营规则仍未配置。

## 边界与验收案例

- 本人有效待支付订单只建立一份准备，金额由订单读取，不接收客户端金额/状态/渠道；同键重试回原ID，换键同订单/同键不同订单均明确冲突。
- 准备不会改库存、订单版本、支付状态或延长预占期限；准备记录不是渠道处理中。
- PREPARED仅允许首次关闭至CLOSED；顾客取消/后台超时在同一事务关闭准备并释放库存。并发准备/取消没有遗留打开记录，重复取消/worker只关闭一次。
- 晚期创建审计失败不留准备记录；关闭审计失败不提前释放库存或取消订单，原操作可重试。
- 绕过API的错误金额/归属、真实渠道/成功状态、无事件、快照改写/删除/重开及原订单直接取消均受数据库约束保护。
- 本人归属、后台order.read和显式仓库范围不放宽；API不返回幂等键、请求编号、密钥或联系资料。
- 页面连接隔离真实API，验证创建响应丢失、重新进入GET核实、加载/读取错误恢复、取消关闭及手机/桌面显示。

## 实际实现与迁移

新增payment_preparations/payment_preparation_events，迁移202611010002_payment_preparation。order_id及(user_id,key)唯一，金额/币种/渠道和归属是不可变快照；SQL CHECK仅允许CNY、DISABLED、PREPARED/CLOSED，关闭时间/原因完整。延迟约束核对订单金额/归属、建立期限、状态及审计事件，准备快照不可修改/删除，事件追加后不可改删。

POST /consumer/orders/:id/payment-preparation只接受空对象及UUID键，先复验会话，按用户/键串行化并锁本人订单；同键历史重放先于截止/取消校验。GET返回{enabled,intent}，其中enabled仅表示可保存本地开发准备。后台订单详情新增可空paymentPreparation。原订单金额/收货加密、仓储限制和支付NOT_STARTED约束保持。

库存释放内核在同一事务关闭准备并追加CONSUMER或SYSTEM事件；无准备的旧订单行为保持。没有发起渠道请求，因此直接关闭DISABLED准备是本地事实，不是渠道关单、退款或支付对账。未来真实渠道状态需要独立迁移/验签/查单/关单和补偿设计，不能直接复用此准备状态冒充付款处理中。

本次无依赖、锁定版本或数据库技术变更；保留原UI文件和已有配置。未提供商户资料或经营规则时继续关闭真实交易。
