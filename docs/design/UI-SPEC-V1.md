设计目标：保留原图的清爽绿色和高效率购买路径，统一品牌、状态与金额口径。当前规格与流程验证界面尚未完成原图视觉/产品可用性验收。2026-10-28负责人指出明显偏差，暂停新增业务，优先调整UI；见[偏差与调整方向](UI-ALIGNMENT-2026-10-28.md)。此前功能通过不代表界面完成。

## 2. 页面统一状态

所有数据页：首次加载骨架、正常、空、网络失败重试、无权限/登录失效。商品页另有缺货/下架；订单页另有处理中/冲突/未知结果。提交按钮含 loading 与防重复，但不能替代后端幂等。

高风险操作：显示操作对象、金额/数量与结果影响；退款、库存调整、送达等确认一次即可，不叠加无意义弹窗。失败保留填写内容；未知结果提供查询，不鼓励盲目重复提交。

## 4. 关键购买页面线框

```text
C06 确认订单
┌ 收货地址：演示小区 / 楼栋 / 房号       更换 ┐
│ 联系人 / 脱敏电话；不支持当前地址则阻止提交 │
├ 商品明细（原单价、规格、数量、逐行金额）  ┤
│ 商品金额                                  31.70 │
│ 配送费                                     3.00 │
│ 应付                                      34.70 │
├ 配送说明 / 备注（不承诺准确到达时间）     ┤
└ 应付 ¥34.70                 [提交并支付] ┘

C07 支付结果
  确认中：正在核实支付结果 → 自动查询/查看订单
  成功：支付已确认 → 查看订单
  未完成：保留待付订单 → 订单有效期内继续支付
  待核实：请勿重复购买 → 查看订单/联系客服
```

报价变化对话框明确旧/新商品行与总价，由顾客再次确认。提交超时后先用原幂等键查询订单，再决定重试。金额由统一样例数据生成，设计稿不单独手填不同总价。

## 8. 响应式与适配

- 消费者以375逻辑像素设计，至少检查320/375/414宽、安全区、长商品名、大字体和软键盘；最终以微信真机为准。
- 后台优先1280/1440宽，表格允许横向滚动；财务/商品复杂表单不强行缩成手机表格。
- 移动作业端以360–430宽设计，列表卡片化、固定主操作、安全区和单手操作；仓库与骑手不同角色入口。
- 状态不只使用红绿区分，增加文字与图标；输入框有持久标签；错误信息指向具体字段。

## 9. 设计验收与实现映射

每个页面开发前形成状态表、字段和 API 关联；组件优先 ProductCard、Price、QuantityStepper、AddressCard、OrderStatus、AmountBreakdown、TaskCard、StockBadge、EmptyState、ErrorState。

先完成 C01/C04/C05/C06/C07、A03/W01/A08、R02/R03 的可交互实现，再扩展相同组件。浏览器截图检查布局与状态；小程序编译、开发者工具与真机验收分别记录，不将网页模拟壳当作最终小程序。

## 已实现隔离报损工作台（2026-10-28）

后台与移动作业页共享组件：立即隔离、分页隔离记录、带数量/效期/库位提示的隔离详情、处置申请/列表/详情、独立审批、报损必选实物确认和必填说明、带原因取消。申请人显示换另一员工审批提示；草稿不预扣，取消不恢复可售。数量动作后刷新上方账面、位置及当前隔离详情；跨仓切换重新挂载，分页与初始异步请求有卸载保护。列表可从上方库存位置按规格筛选/加载。服务端仍是权限及冲突裁决方。

## 已实现收货纠错工作台（2026-10-28）

后台/H5：选择库存位置→核对原单/原行、原数量、已冲回/剩余额度与当前位置自由数→提交误录原因和数量→另一员工审批→原单/实物确认及说明→过账。状态详情保留申请、审批、取消和核验说明；位置版本变化提示取消重建。列表UUID游标分页，按钮权限仅辅助，后端仍独立裁决。过账刷新原额度、上方账面与位置。

## 实物盘点UI接续（2026-10-28）

盘点以单据列表为入口，按当前已载入状态筛选；新建与详情分别用独立对话窗口。新建显示冻结影响，详情按状态及既有权限显示实盘提交、独立审批、过账与终止；失败保留填写值，刷新当前单据用于重新核对。UI验收使用合成接口响应，不能替代真实PostgreSQL或实物验收。完整UI及下一页范围见[接续复核](../verification/UI-CONTINUATION-2026-10-28.md)。业务/API/数据契约未调整。

## 隔离/报损及纠错UI接续（2026-10-28）

W04以隔离记录/处置申请两个列表入口组织；隔离详情提供处置申请，单据详情根据状态与权限提供审批/过账/取消，新建隔离用独立窗口。W01纠错单以列表和状态筛选进入详情，新建时先选择商品批次位置并加载原单及额度；详情展示原单额度与独立审批、核验、过账。页面失败保留输入，重试复用原幂等键，接口已确认成功但刷新失败时关闭已完成的新建表单，避免重复创建。仍由服务端裁决权限、版本与库存保护；规则/API/数据模型未改。验收见[本轮报告](../verification/UI-STOCK-TASKS-2026-10-28.md)。

## 库位/核对UI与移动角色入口（2026-10-28）

W02/A05库位区默认展示批次位置，存储库位、移位历史和核对报告独立切换；所有详情与新建/移位/核对/解除核对暂停均在对象窗口内办理。报告是不可改的历史快照，不能据此宣称当前销售已恢复；核对窗口读取当前账面和版本，解除仍由服务端重新核对。正常列表不默认展示完整UUID，内部编号放入追溯展开区。

手机仓管入口聚焦仓储；无仓管写权限的PICKER仅显示库存总览、库位与核对查询。拣货领取、打包及出库尚未实现，不提供虚假任务。权限与库存规则/API/数据模型不变，见[交付报告](../verification/UI-LOCATIONS-2026-10-28.md)。

## 收货入库UI接续（2026-10-29）

W01按单据列表→独立详情→核验并审核/入库组织，来源/批次搜索与状态筛选仅作用于已载入单据；UUID仅在详情追溯展开区显示。新建可添加现有API允许的多行，不重复选择同一SKU，成本用十进制文本转换为整数分，效期按北京时间填写。手机表单标题、错误反馈与保存操作保持可见。

详情由本仓受权GET读取，独立加载/失败重试；审核不加库存，入库前说明进入DEFAULT并生成批次/流水。确认操作失败保留核验状态，刷新单据后必须重新核验；状态变化后不继续显示旧动作。未知保存响应在当前窗口保留原内容/幂等键重试，未知入库响应可刷新真实详情确认，不乐观显示成功。真实库存与UI分开验收，见[报告](../verification/UI-RECEIPTS-2026-10-29.md)。
