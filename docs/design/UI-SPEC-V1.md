## 2. 页面统一状态

所有数据页：首次加载骨架、正常、空、网络失败重试、无权限/登录失效。商品页另有缺货/下架；订单页另有处理中/冲突/未知结果。提交按钮含 loading 与防重复，但不能替代后端幂等。

高风险操作：显示操作对象、金额/数量与结果影响；退款、库存调整、送达等确认一次即可，不叠加无意义弹窗。失败保留填写内容；未知结果提供查询，不鼓励盲目重复提交。

```text

│ 应付                                      34.70 │

C07 支付结果
  确认中：正在核实支付结果 → 自动查询/查看订单
  成功：支付已确认 → 查看订单
```

报价变化对话框明确旧/新商品行与总价，由顾客再次确认。提交超时后先用原幂等键查询订单，再决定重试。金额由统一样例数据生成，设计稿不单独手填不同总价。

## 8. 响应式与适配

- 消费者以375逻辑像素设计，至少检查320/375/414宽、安全区、长商品名、大字体和软键盘；最终以微信真机为准。
- 后台优先1280/1440宽，表格允许横向滚动；财务/商品复杂表单不强行缩成手机表格。
- 移动作业端以360–430宽设计，列表卡片化、固定主操作、安全区和单手操作；仓库与骑手不同角色入口。
- 状态不只使用红绿区分，增加文字与图标；输入框有持久标签；错误信息指向具体字段。

## 已实现隔离报损工作台（2026-10-28）

后台与移动作业页共享组件：立即隔离、分页隔离记录、带数量/效期/库位提示的隔离详情、处置申请/列表/详情、独立审批、报损必选实物确认和必填说明、带原因取消。申请人显示换另一员工审批提示；草稿不预扣，取消不恢复可售。数量动作后刷新上方账面、位置及当前隔离详情；跨仓切换重新挂载，分页与初始异步请求有卸载保护。列表可从上方库存位置按规格筛选/加载。服务端仍是权限及冲突裁决方。

## 已实现收货纠错工作台（2026-10-28）

后台/H5：选择库存位置→核对原单/原行、原数量、已冲回/剩余额度与当前位置自由数→提交误录原因和数量→另一员工审批→原单/实物确认及说明→过账。状态详情保留申请、审批、取消和核验说明；位置版本变化提示取消重建。列表UUID游标分页，按钮权限仅辅助，后端仍独立裁决。过账刷新原额度、上方账面与位置。

## 收货入库UI接续（2026-10-29）
